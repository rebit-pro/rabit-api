# MoreFoto — короткая памятка по проверке волн

Актуально на **21 сентября 2026**. Здесь перечислены пройденные проверки и действия для их ручного повторения. Галочки оставлены пустыми для вашего прогона. Исторические результаты относятся к версиям соответствующих волн; текущая браузерная регрессия проверяет их доступные пользовательские сценарии вместе с C4.

## Какой стенд сейчас проверять

Для ручной проверки опубликованного frontend используйте **https://app.morefoto36.ru**. Он собран из актуального `main` без mock-адаптера и обращается к stage backend. Проверка `POST /api/v1/auth/login` без полей возвращает JSON `400`; браузерное окно Basic Auth больше не появляется.

Тестовые логины ниже подготовлены только в локальном изолированном E2E-стенде. Они **не являются логинами опубликованного app.morefoto36.ru**: попытка входа `organizer@example.invalid` на опубликованном стенде возвращает `Invalid credentials`. Рабочие stage-логины в репозитории и в этот документ не записываются; их должен выдать владелец окружения. Не используйте локальный пароль на внешнем адресе.

На опубликованном адресе без выданной stage-учётной записи можно проверить только загрузку приложения, отсутствие Basic Auth, экран входа, ошибки пустых/неверных данных и сетевые ответы. Полные сценарии кабинета выполняются на локальном стенде по инструкциям ниже.

**C3 и C4 слиты в main; F1 слита в main. E4 опубликована в [draft PR №30](https://github.com/rebit-pro/rabit-api/pull/30) и ожидает исправления проверки перед merge.** Локальный стенд ниже работает с настоящими API, Bitrix и отдельной MySQL. Рабочий frontend находится в `frontend/` репозитория RaBit API; соседний MoreFoto сохраняет продуктовый план.

## Вход на подготовленный стенд

**[Открыть MoreFoto](http://localhost:42006/login)** · [Учреждения](http://localhost:42006/cabinet/institutions) · [Каталог](http://localhost:42006/cabinet/catalog)

Стенд оставлен запущенным на этом компьютере. Доступ с Windows проверен: HTTP 200. Все девять входов проверены через настоящий API. Общий пароль **только этих тестовых учётных записей**:

```text
A8-test-only-password!42
```

| Логин | Роль и подготовленный доступ |
|---|---|
| `organizer@example.invalid` | Организатор: каталог и все учреждения. Основной вход. |
| `another-organizer@example.invalid` | Второй организатор: для одновременного редактирования. |
| `curator@example.invalid` | Куратор: только «C3 Назначенная область». |
| `head@example.invalid` | Заведующая: только «C3 Назначенная область». |
| `c4-curator@example.invalid` | Куратор: только «C4 Назначенное учреждение». |
| `c4-head@example.invalid` | Заведующая: только «C4 Назначенное учреждение». |
| `teacher@example.invalid` | Воспитатель: профиль доступен, каталог и редакторы учреждений запрещены. |
| `another-teacher@example.invalid` | Второй воспитатель с такими же ограничениями; назначенных групп на этом стенде нет. |
| `unassigned@example.invalid` | Активная учётная запись без профиля сотрудника: «Доступ к кабинету не назначен». |

Для смены роли нажмите «Выйти». Для двух одновременных пользователей используйте разные профили браузера либо обычное и приватное окно. Две обычные вкладки одного профиля делят авторизацию. **Повторный вход под одним логином отзывает предыдущую сессию** — для конфликта редакторов нужны два разных организатора.

Источник логинов и пароля — [подготовка тестовой БД](../../api/tools/e2e/prepare.php). Это искусственные данные из E2E-набора. Производственные, SSH, GitHub и другие рабочие пароли в памятку не включены.

## E4 — приватная галерея и серверная корзина

Перед проверкой E4 на `app.morefoto36.ru` сверьте, что опубликованы и frontend, и stage backend с миграциями E4. Открыть `/g/<token>` можно только с действующим ключом, выданным внутренним lifecycle; публичная выдача ссылок и реальные заказы относятся к последующим F2/E5/G2.

Для локального E4-стенда нужны искусственные данные из E2E-прогона и токен capability, который создаёт подготовка стенда. Логины те же, что указаны выше для локального стенда; для серверного quote используется организатор. Сценарии:

- [ ] Открыть подготовленную приватную галерею `/g/<gallery-token>` и убедиться, что разрешённые снимки загружаются только через защищённые `thumb/preview` URL.
- [ ] Открыть preview без Bearer — ожидается `401`; с Bearer — `200 image/webp` и `Cache-Control: no-store`. Прямой путь к `/upload/morefoto/previews/` должен быть закрыт.
- [ ] Добавить физический товар, изменить количество и перезагрузить страницу. Итог корзины каждый раз приходит от `POST .../quotes`; клиентский mock и неподтверждённая сумма не используются.
- [ ] Проверить отказ чужого `assignmentId`, неизвестного товара, повторной строки и количества вне диапазона. Для одной фотографии, назначенной двум детям, скидка считается отдельно по каждому `assignmentId`.
- [ ] Для `preparing` снимки скрыты, для `closed` новый quote запрещён. Checkout, заказ и оплата пока недоступны.

Автоматический E4 gate зафиксирован в [verification.json](../waves/e4/verification.json): backend/frontend и 59 браузерных сценариев прошли, анонимное превью возвращает `401`, авторизованное — `200`. Post-browser проверка quote на реальной MySQL прошла; отдельно проверены desktop/mobile галерея, корзина и название пункта F1.

## F2 — подготовка и факт передачи ссылки

Локально F2 проверяется на стенде `make e2e-up` после миграции `20260922150001`; на `app.morefoto36.ru` — только после публикации backend/frontend F2 и её миграции. Данные — тестовые группы с готовыми кадрами и активным товаром.

- [ ] Под организатором открыть «Ссылки и сроки». Для новой группы видны проблемы готовности; после разметки всех кадров и наличия товара кнопка «Проверить ссылку» доступна. До проверки ссылки нет — «Ссылка появится после проверки группы».
- [ ] Отметить три проверки и подтвердить. Статус «Готова к передаче», «Копировать ссылку» копирует `/g/<ключ>`; галерея по ней показывает состояние подготовки без снимков.
- [ ] Переименовать группу или изменить её условия — статус снова «Требует проверки», передача без новой проверки отклоняется.
- [ ] Под воспитателем группы отметить передачу с текущими датой и временем МСК. Статус «Приём открыт», в карточке сроки «Приём заказов до» (+7 дней) и «Доставка до» (+7 дней); галерея открыта и считает корзину. Карточка съёмки показывает «Ссылка передана».

## Как пересоздать или остановить стенд

Этот адрес локальный и временный. Обновление страницы сохраняет данные. Остановка/перезапуск контейнера MySQL или очистка стенда может удалить их: БД хранится в tmpfs. Если адрес перестал открываться, нужен новый запуск; это не внешний опубликованный сайт.

Для нового полного прогона нужна **свежая БД**. Из корня C4 в WSL:

```sh
cd /home/user/rebit-p2p/api/var/worktrees/c4
python3 tools/run-browser-e2e.py up
```

Команда напечатает новый адрес и путь `State`. Затем выполнить с этим путём:

```sh
python3 tools/run-browser-e2e.py test --state /absolute/path/from/State/state.json
```

После тестов стенд остаётся включённым с подготовленными данными. Не запускать полный набор повторно на уже изменённой вручную БД. При пересоздании искать учреждения по названиям: UUID в ссылках этой памятки относятся к запуску от 13.09.2026.

**Остановить именно текущий стенд и очистить его тестовые ресурсы**, когда ручная проверка закончена:

```sh
cd /home/user/rebit-p2p/api/var/worktrees/c4
python3 tools/run-browser-e2e.py down --state /home/user/rebit-p2p/api/var/worktrees/c4/api/var/e2e/rabit-e2e-df39f10033d5/state.json
```

Отчёт текущего запуска и сведения о состоянии сохранены локально в `api/var/e2e/rabit-e2e-df39f10033d5/`; сверка учётных записей и данных — в `api/var/manual-review/data.json` без токенов. После каждой следующей волны памятка дополняется её действиями, ожидаемым результатом, фактом проверки и доступными тестовыми данными.
