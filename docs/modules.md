# Модули RaBit API

| Модуль | Состояние | Ответственность |
| --- | --- | --- |
| `rebit.share` | Сохранён | HTTP/DTO/валидация, файлы, аудит, логирование, кеш, Messenger, общие контракты |
| `rebit.auth` | Сохранён | Вход, регистрация с кодом, выход, разрешение токена |
| `rebit.notification` | Восстановлен | Приём заявок с сайта, синхронная доставка в Telegram и резервный email |
| `rebit.leadhunter` | Восстановлен | Сбор и фильтрация внешних заявок, дедупликация, доставка в Telegram с резервным email |
| `rebit.dev` | Технический инструмент | Правила форматирования и помощь разработке |
| `sprint.migration` | Технический инструмент | Версионирование схемы/настроек |

Из приложения удалены четыре торговых модуля: `rebit.bybit`, `rebit.exchange`, `rebit.identity`, `rebit.wallet`, их регистрации, потребители очередей и торговые контракты Share. Общие SMTP/Telegram transport и audit consumer остаются в Share.

`rebit.notification` принимает заявки с публичной формы через `POST /api/v1/lead` и доставляет контакты, описание и опциональный файл в Telegram. При сбое основного канала и настроенном получателе используется email. Это синхронный сценарий: торговые типы и email-шаблоны прежней очереди, publisher и consumer не восстановлены. Общую асинхронную доставку предстоит проектировать под конкретные события RaBit API; Messenger-примитивы уже находятся в Share.

`rebit.leadhunter` — самостоятельная действующая лидогенерация. Модуль восстановлен после ошибочного удаления: команда `app:leadhunter:scan` запускается по cron, читает RSS fl.ru, применяет правила и доставляет заявки напрямую через `TelegramBotApiClient` из Share. При недоступности Telegram и настроенном `REBIT_LEADHUNTER_FALLBACK_EMAIL` используется email. Отдельный notification consumer для LeadHunter не нужен; новых HTTP-маршрутов LeadHunter не добавляет.

MoreFoto развивается в собственных будущих модулях: [каноническая карта](../../MoreFoto/docs/04-bitrix-modules/README.md). Они не создаются в рамках выделения основы. Общие интерфейсы находятся в `rebit.share/lib/Application/Contract/`; реализация принадлежит модулю-поставщику. Auth отвечает за идентификацию, а права на конкретные ресурсы проверяет модуль-владелец сценария.
