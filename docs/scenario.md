# Сценарии RaBit API

1. Пользователь запрашивает код регистрации и подтверждает его через Auth.
2. Auth проверяет учётные данные, выдаёт токен и отзывает его при выходе.
3. Share предоставляет общий механизм загрузки файла и технического аудита.
4. По cron запускается `app:leadhunter:scan`: LeadHunter читает RSS fl.ru, отбирает заявки по правилам и сохраняет новые по уникальной паре `(source, guid)`.
5. LeadHunter отправляет накопившиеся заявки в Telegram через Share. При ошибке основного канала и настроенном `REBIT_LEADHUNTER_FALLBACK_EMAIL` использует резервный email; недоставленные заявки повторно обрабатываются следующими прогонами в пределах установленного числа попыток.

6. Notification принимает публичную заявку с сайта через `POST /api/v1/lead`: проверяет контакты и опциональное вложение, отсекает заполненный honeypot и синхронно отправляет заявку в Telegram. При сбое и настроенном получателе использует резервный email. Этот вход независим от поиска внешних заявок LeadHunter; торговая очередь не участвует.

Это описание существующего кода. Ограничения проверки токена и владения файлом перечислены в [аудите](audit-rabit-api.md).

Пользовательские сценарии MoreFoto и их API определены в [документации MoreFoto](../../MoreFoto/docs/05-rest-api/README.md). Они будут реализованы отдельными продуктовыми модулями; перенос торговой логики в них не предусматривается.
