# F3 — короткая ссылка группы

## Цель

Сотрудник копирует для родительского чата короткую ссылку на галерею группы на собственном домене — сохраняемую и непредсказуемую. Старые 64-символьные ссылки продолжают работать. Требование R05 плана владельца `docs/plans/OPS-telemos-feedback-plan/` (встреча 11.10.2026); граф: `docs/waves/graph.json`, волна F3 (MVP, открывает N3).

## Контекст

- Ветка `codex/f3-short-group-link` от main 0d02adf (merge #160). Зависимости F2, E4, E7 слиты; решения D05, D07, D10 приняты. `endpointIds` F3 пуст: новых каталогизированных эндпоинтов не планировалось.
- J2 приостановлена (ветка `codex/j2-buyer-files-email` без PR), поэтому отметку J4 `merged` в графе вносит F3.

## Факты инвентаризации

- **Ключ галереи** (`mf_gallery_capability`): `TOKEN_HASH` (PK) + с F2 сырой `TOKEN` (решение F2: риск утечки БД принят), `REVISION`, `REVOKED`, `CREATED_AT`; `GalleryCapabilityLifecycle::issue()` — `random_bytes(32)`. Переиздания нет, отзыв — только в E2E. На `TOKEN_HASH` ссылаются `mf_cart_quote`, `mf_order`, `mf_order_checkout` (RESTRICT).
- **Выдача ссылки сотруднику:** HND-02 отдаёт `galleryToken` (`GalleryLinks::current()`); HND-03 вызывает `ensure()` под блокировкой группы; `CREATED_AT` ключа — нижняя граница T0 (`SENT_AT_BEFORE_LINK`), поэтому псевдоним не создаёт и не трогает строку ключа.
- **Frontend:** `LinksScreen.vue` строит `origin + '/g/' + token` и копирует; `/g/:token` без проверки формата; локальное хранилище (корзина по группе, `rememberedGallery` проверяет 64 hex, вопросы куратору по токену).
- **Проверка токена:** шесть request DTO (`^[a-f0-9]{64}$`, 404 `GALLERY_NOT_FOUND`), `GalleryAccess`; Commerce и Support сами считают `sha256(token)` для квоты, заказа, оформления и вопросов.
- **Логи:** путь `/g/` и `/api/v1/public/galleries/` исключены из access-логов frontend и backend nginx; тест `private-links-log.test.mjs` не проверяет `/g/` и backend.
- **Лимитов запросов на публичную галерею нет.**

## Решения (приняты 12.10.2026)

Ответы пользователя: **DEC-01 — 10 символов** (не рекомендованные 12; стойкость ~3,6 года упорного перебора при отсутствии лимитов — принято), **DEC-02 — `app.morefoto36.ru/g/…`**, **DEC-03 — только короткая**, **DEC-04 — заменить на длинный**.

Варианты, как их предлагали:

- **F3-DEC-01. Длина псевдонима** (строчные латинские буквы и цифры без похожих 0/o, 1/l — 32 символа, 5 бит на символ). Оценка перебора при ~10 000 групп и 1000 запросов в секунду:

  | Символов | Бит | Время до первого попадания | Пример |
  | --- | --- | --- | --- |
  | 10 | 50 | ~3,6 года | `/g/k3m9x2q7v4` |
  | **12** | 60 | ~3 600 лет | `/g/k3m9x2q7v4p8` |
  | 16 | 80 | практически никогда | `/g/k3m9x2q7v4p8w6tz` |

  Рекомендация: 12.
- **F3-DEC-02. Домен.** Рекомендация: текущий `app.morefoto36.ru/g/<псевдоним>` — без изменений инфраструктуры. Альтернатива: корневой `morefoto36.ru/<псевдоним>` — короче, но нужна настройка nginx/DNS основного сайта вне репозитория.
- **F3-DEC-03. Что копирует сотрудник.** Рекомендация: короткую ссылку; длинная продолжает работать, но в интерфейсе не показывается. Альтернатива: обе (короткая основная, длинная — отдельной кнопкой).
- **F3-DEC-04. Адресная строка у родителя.** Рекомендация: короткая ссылка открывает галерею и заменяет адрес на длинный `/g/<токен>` — корзина, заказы и вопросы работают как сейчас. Альтернатива: короткий адрес остаётся в строке — все публичные эндпоинты и хранилища принимают псевдоним (заметно больше изменений).

Технические решения (по умолчанию):

- **T-01. Хранение:** таблица `mf_gallery_alias` (`ALIAS` ascii_bin UNIQUE, `TOKEN_HASH` UNIQUE → ключ галереи, CASCADE при удалении группы), псевдоним открытым текстом — как ключ по решению F2, чтобы сотрудник мог его копировать.
- **T-02. Создание:** в `ensure()` под блокировкой группы (HND-03); повтор возвращает тот же псевдоним; коллизия — повтор генерации (UNIQUE). Миграция создаёт псевдонимы действующим ключам с сохранённым `TOKEN`. GET (HND-02) ничего не создаёт.
- **T-03. Разрешение:** MED-01 `GET /public/galleries/{gallery_token}` принимает и псевдоним; ответ дополняется `token` (длинным) для перехода по F3-DEC-04. Отозванный ключ — 404, как для длинной ссылки. Новых API ID нет.
- **T-04. T0 и даты:** копирование и создание псевдонима не меняют передачу, T0 и сроки.
- **T-05. Логи:** путь прежний (`/g/`), исключения nginx действуют; тест логов frontend дополняется `/g/<псевдоним>`. Backend nginx получает псевдоним только в `/api/v1/public/galleries/`, этот префикс уже исключён, конфиг не меняется (отдельного теста нет: frontend-тесты не видят `api/`).
- **T-06. Отзыв/переиздание:** псевдоним живёт, пока действует его ключ; новый ключ получает новый псевдоним.

## Scope (после согласования)

1. **Media:** миграция `mf_gallery_alias` + заполнение; генератор псевдонима; `ensure()`/`current()` с псевдонимом; разрешение псевдонима в MED-01; удаление группы.
2. **Handoff:** HND-02 отдаёт `galleryAlias`; контракт `GalleryLinkInterface`.
3. **Frontend:** копирование и «Открыть галерею» — короткая ссылка; `/g/:token` принимает псевдоним и заменяет адрес.
4. **Тесты:** PHPUnit (генератор, коллизия, повтор, отозванный ключ, архитектура), frontend unit, live E2E (короткая и длинная ссылка, отзыв, неизвестный псевдоним, окна продаж, desktop/mobile), верификатор MySQL.
5. **Документация:** `docs/waves/f3/`, граф (J4 `merged`, F3 `review`).

## Исключено

- QR-коды, внешние сокращатели, переиздание ключа из интерфейса, лимиты запросов (отдельная задача).

## Риски

- Без лимита запросов стойкость держится только на длине псевдонима: 10 символов (50 бит) — ~3,6 года перебора при 1000 запросов/с и ~10 000 групп (F3-DEC-01, принято пользователем). Лимит запросов на публичную галерею — отдельная задача.
- Ключи до F2 без сохранённого `TOKEN` псевдонима не получают (их ссылку и так нельзя скопировать).

- Desktop/mobile без горизонтального скролла.
