# Issues #109 и #110 — тексты оформления после G1 и формат телефона в заказе

## Цель и контекст

- [#109](https://github.com/rebit-pro/rabit-api/issues/109). После G1 оплата картой через ЮKassa работает, но
  оформление и «Заказы» говорят про демонстрацию и отсутствие оплаты.
- [#110](https://github.com/rebit-pro/rabit-api/issues/110). Телефон покупателя в заказе и у куратора выводится
  сырым значением `+79001234567`; нужен единый формат `+7 900 123-45-67`.

Это issue-ветка, не волна: `docs/waves/graph.json` не меняется.

- Ветка: `codex/issues-109-110-order-texts-phone`.
- Worktree: `/home/user/rabit-api-worktrees/issues-109-110-order-texts-phone`.
- Base: `origin/main` `23642d4` (merge PR #112, `morefoto.legal`).
- Изменения только во frontend; backend, хранилище и API не меняются.

## Установленные факты (main 23642d4)

- Настоящий (live) режим и демо разделены флагом `isMockApiEnabled`: `OrderPage` → `OrderLiveScreen` в live и
  `OrderScreen` в демо; `CuratorPage` → `StaffOrdersLiveScreen` в live и `CuratorScreen` в демо. `CheckoutForm` общий,
  `useCheckout` выбирает live- или demo-логику.
- После PR #112 подпись отметки состава в live — «Состав заказа проверен», в демо — «Состав и демонстрационные
  условия проверены». Кнопка «Создать тестовый заказ» и подпись «Деньги не списываются…» — в обоих режимах.
- Остатки в live, кроме названных в issue:
  - `CheckoutContacts.vue`: вводная «Укажите тестовые данные…» и `receipt-unavailable` «Способ получения чека
    появится вместе с оплатой. Сейчас заказ сохраняется без списания денег.» (в live `receiptAvailable` всегда `false`);
  - `CheckoutTerms.vue`: «В демонстрации выдаются тестовые файлы.» показывается и в live;
  - `FeatureUnavailablePage.vue` (сюда live перенаправляет старую демо-страницу оплаты `/orders/access/:key/payment`):
    «Онлайн-оплата заказов появится после подключения платёжного сервиса.».
- Остальные найденные «демонстрац…»/«тестов…» — в демо-экранах (`OrderScreen`, `PaymentScreen`, `PaymentPanel`,
  `PaymentStatus`, `OrderContacts` «Email · демонстрация», `CuratorScreen` и т. д.) и остаются: там это правда.
- Признака тестового режима платежей во frontend нет: `PaymentQuote` (`quote`, `quoteToken`, `orderVersion`, `canPay`,
  `precedingAttemptId`, `activeAttemptId`, `paymentMethods`), `CatalogCapabilities` (`receiptChannels`,
  `purchaseEnabled`), `BuyerOrder` и env `VITE_*` (только `VITE_API_URL`, `VITE_API_MOCKS_ENABLED`) его не содержат.
  В `morefoto.payment` поля о тестовом магазине в ответах API тоже нет.
- Хелпер телефона уже есть: `ui/field-values.ts` `displayPhone()` — маска поля ввода `+7 (900) 123-45-67`
  (`UiPhoneField` на blur), покрыт `tests/commerce/ui-values.test.mjs`. Нестандартные и нероссийские номера он
  возвращает как есть.
- Телефон выводится в `OrderLiveFacts.vue` (live: страница заказа покупателя и карточка заказа у куратора),
  `StaffOrdersLiveScreen.vue` (строка списка «Заказы»), `OrderContacts.vue` (демо: страница заказа и карточка
  куратора). Строка `OrderContacts.vue:18` из issue — демо-вариант; live-страница покупателя — `OrderLiveFacts`.

## Решения

- **R1 (#109, выбор пользователя).** Отметка — «Состав и условия проверены» в обоих режимах (вместо ветвления
  live/демо), кнопка — «Оформить заказ». Подпись под кнопкой — «Оплата — на странице заказа после оформления. Для заказа
  создаётся отдельная личная ссылка.». Сообщения ошибки отметки приведены к той же формулировке.
- **R2.** Подсказку «Оплата появится после подключения платёжного провайдера» у плитки «Заказов найдено» убрать без
  замены: статус оплаты уже есть у каждой строки списка и в фильтре «Оплата».
- **R3.** Плашку тестового магазина не добавлять: признака во frontend нет, backend в этой ветке не меняется.
  Ограничение фиксируется в PR; для плашки нужен отдельный issue на поле API (например, `testMode` в
  `PaymentQuote`).
- **R4.** Остатки в live исправить по месту: вводная контактов и демо-фраза условий — только в демо;
  `receipt-unavailable` — «Выбор канала для чека появится позже. Оплата — на странице заказа после оформления.»;
  `FeatureUnavailablePage` — «Эта страница есть только в демонстрационной версии. Заказ оплачивается на его личной
  странице.».
- **R5 (#110).** Переиспользовать разбор `displayPhone()`: общий приватный `russianPhoneDigits()` в
  `field-values.ts` и новая `formatPhone()` для отображения `+7 900 123-45-67`. `displayPhone()` (маска ввода со
  скобками) не меняется. `formatPhone()` применяется в `OrderLiveFacts`, `StaffOrdersLiveScreen`, `OrderContacts`.
