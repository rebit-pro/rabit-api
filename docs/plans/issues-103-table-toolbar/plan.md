# Issue #103 — панель выбора без сдвига таблицы и выразительная шапка

## Цель и контекст

Замечание пользователя 2026-09-25 после выкатки #91: на «Сотрудниках» плашка «Выбрано: N · Удалить выбранных»
появляется над таблицей и сдвигает её; шапка таблицы бледная, сортировка обозначена текстовыми `↕ ↑ ↓`.
Issue [#103](https://github.com/rebit-pro/rabit-api/issues/103). Ветка `codex/issues-103-table-toolbar` от `origin/main`
`03f4e3b`. Не продуктовая волна, граф не меняется.

## Scope

- `UiDataTable`: постоянная панель над таблицей фиксированной высоты — подпись «Название · N записей» без выбора,
  слот `selection` при выборе (по умолчанию «Выбрано: N»); `<caption>` визуально скрыт, но остаётся для скринридеров.
- `UiDataTable`: шапка — фон `--mf-color-surface-2`, `--mf-text-md` semibold, нижняя граница 2px; иконки
  `mdi-arrow-up`/`mdi-arrow-down` (primary) у активной колонки, приглушённая `mdi-swap-vertical` у остальных.
- Реестр иконок: три новые иконки.
- «Сотрудники»: действия выбора переезжают в слот `selection`; `data-testid="staff-bulk"` сохраняется.
- Пример UI-кита: внешняя плашка переезжает в слот `selection` (иначе при выборе дублировалась бы).
- Mobile: в панели «Удалить» и крестик вместо «Удалить выбранных»/«Снять выбор» (доступные имена прежние);
  пояснение про свою учётку — в диалоге подтверждения, чтобы панель оставалась в одну строку.
- Исключено: остальные экраны (#92), пагинация (пользователь доволен).

## Решения и риски

- D1. Панель внутри общего компонента, а не зарезервированное место на экране: так же ведут себя все таблицы, и
  следующие экраны из #92 получат массовые действия без сдвига.
- D2. Высота панели — 48px (кнопки compact 40px), одинаковая в обоих состояниях; на mobile панель переносится
  в две строки только при выборе — проверить визуально, при необходимости разрешить перенос без изменения высоты
  первой строки.
- Риск: изменение шапки видно на всех таблицах (организации, куратор, печать, пример UI-кита) — визуальная проверка.
