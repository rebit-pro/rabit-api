# Issue #123 — международный телефон покупателя (`+8…`) не превращается в российский

## Цель и контекст

[#123](https://github.com/rebit-pro/rabit-api/issues/123) — неблокирующая находка ревью PR #118. Номер
`+85291234567` (Гонконг) сейчас искажается в российский `+75291234567`: backend `BuyerPolicy` сохраняет его так,
маска поля `displayPhone` (по blur в `UiPhoneField`) и readonly-форматтер `formatPhone` показывают `+7 529 123-45-67`.
Причина одна: сначала удаляется `+`, затем любые 11 цифр с начальной `8` считаются национальной российской записью.

Это issue-ветка, не волна: `docs/waves/graph.json` не меняется.

- Ветка: `codex/issues-123-international-phone`, worktree `/home/user/rabit-api-worktrees/issues-123-international-phone`.
- Base: `origin/main` `4fc9dce`.

## Правило (одно для frontend и backend)

- Явный международный префикс — `+` перед первой цифрой (`+852…`, `(+852) …`, `+8 …`).
- `8XXXXXXXXXX` (11 цифр) без явного `+` — российский номер, хранится как `+7XXXXXXXXXX`.
- `+7XXXXXXXXXX` и `7XXXXXXXXXX` — российский номер.
- `+8…` и остальные `+…` — международный номер, цифры сохраняются как есть.
- Проверка допустимых символов и длины 10–15 цифр не меняется.

## Scope

1. Backend `morefoto.commerce` `Domain/Order/Service/BuyerPolicy`: замена `8`→`7` только без явного `+`.
2. Frontend `ui/field-values.ts`: общая функция `phoneDigits` (цифры для хранения по правилу выше);
   `russianPhoneDigits` → на её основе, отсюда исправляются `displayPhone` (маска `UiPhoneField` по blur) и `formatPhone`.
3. Demo-нормализация на том же правиле (из приёмки issue): `orders/services/validation.ts` `normalizeBuyer`
   и правка контактов в `settlement/service.ts`.
4. Unit-тесты: PHPUnit `OrderBuyerPolicyTest`, node `tests/commerce/ui-values.test.mjs`, `checkout.test.mjs`.

## Исключено из scope

- Миграция уже сохранённых искажённых номеров: из `+7529…` нельзя восстановить, был ли ввод `+852…` или `8529…`.
  Описывается в PR, данные не трогаются.
- `rebit.share` `Shared/ValueObject/Phone` (авторизация) — тот же приём `8`→`7` после удаления `+` и дополнение
  10 цифр до `+7`; другой контекст и контракт, в этой задаче не меняется, сообщается отдельно.
- Маска ввода по нажатиям не вводится: `UiPhoneField` форматирует только по blur.
- `make test-e2e` — после ревью, запускает координатор.

## Риски и ограничения

- Ввод `+8 900 123-45-67` (ошибочная «российская» запись с `+8`) теперь сохраняется как международный `+89001234567`.
  Это требование issue: явный `+` — международный префикс.
- Ранее сохранённые искажённые номера остаются `+7…` и показываются как российские.
