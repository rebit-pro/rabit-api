# #192 — гайд для родителей «Как купить фото»

## Цель

Отдельная страница-коллаж для родителей-покупателей: 6 шагов «скриншот телефона + одна строка действия», почти без текста. Ссылку организатор (сестра владельца) прикрепляет к сообщению в чате группы; та же ссылка видна на каждом шаге покупки. Родители платят в основном с телефона. Issue #192, запрос владельца 13.10.2026.

## Контекст

- Ветка `codex/issues-192-parent-buy-guide` от main 60bd97f; рабочая копия `/home/user/rabit-api-worktrees/issues-192-parent-buy-guide`.
- Есть подробная статья `/guide/parent/` (8 шагов, текст для чтения; её актуализация — #188). Ссылка «Как заказать фото» есть только в футере покупателя — на телефоне под длинной корзиной.
- Шаги покупателя (stage `main-20261013161806-96b74b6`): галерея `/g/…` → кадр (выбор продукции списком) → корзина с оформлением `/g/…/cart` (email, два согласия, «Оформить заказ · сумма») → страница заказа `/orders/access/…` («Оплатить», «Скопировать личную ссылку») → ЮKassa → результат оплаты `/orders/payment/…` → заказ «Оплачено», электронные файлы.
- Письма покупателю (ссылка на заказ, J2) пока не отправляются — сохранить личную ссылку заказа важно.
- nginx frontend: `try_files $uri $uri/ /index.html`, статика из `public/` уходит в образ как есть; адрес каталога без `/` сейчас перенаправляется на `http://…` (абсолютный редирект за TLS-прокси).

## Scope

1. Статическая страница `frontend/public/kak-kupit/` (`index.html`, стили, скрипт увеличения, WebP-снимки шагов, картинка превью `og.jpg`).
2. Превью ссылки в мессенджерах: `og:title`, `og:description`, `og:image` (коллаж 1200×630, JPEG), `twitter:card`.
3. Ссылка «Как купить» на шагах покупателя: шапка галереи (блок группы), диалог «Помощь», просмотр кадра, корзина, страница заказа, результат оплаты; футер «Как купить фото» ведёт на новую страницу, подробная статья остаётся ссылкой со страницы гайда.
4. nginx frontend (production, development): `absolute_redirect off`.
5. Замечания владельца к версии 1 (13.10.2026):
   - карточка кадра: «+» у каждого формата вместо радиокнопок и общей кнопки — родитель видит, что к одному кадру можно добавить несколько форматов (KK-DEC-07);
   - страница заказа: «Сохранить в телефон» у каждого фото на телефоне — меню телефона «Поделиться / Сохранить изображение» (KK-DEC-08); «Скачать» и «Скачать всё архивом» остаются;
   - шаг оплаты остаётся с картой; замена на QR-код СБП — #193.

## Исключено

- Подробная статья `/guide/parent/` и остальные статьи базы знаний — #188.
- Письма покупателю — J2. Демо-режим витрины — без ссылки (демо-страницы не для родителей).

## Решения

- **KK-DEC-01.** Статическая страница, не маршрут приложения: открывается быстро без бандла приложения, мессенджеры читают её превью (SPA-превью без JS не видно), выкладка — только frontend. Адрес `https://app.morefoto36.ru/kak-kupit/` (читается как «как купить»).
- **KK-DEC-02.** Основа — `guide.css` и просмотр скриншотов `guide.js` базы знаний (разметка `.shot > a`), свои стили — `kak-kupit.css`. Вид — «отпечатки на столе»: каждый шаг — фотокарточка с белыми полями, номер-наклейка, снимок телефона с красной рамкой вокруг нужной кнопки, подпись одной строкой; лёгкий наклон ±1°. Телефон — одна колонка; от 720 px — две; от 1100 px — три (коллаж). Без внешних шрифтов и библиотек; системный шрифт, токены цвета продукта, светлая тема.
- **KK-DEC-03.** Шаги: 1 «Найдите своего ребёнка», 2 «Выберите фото и формат», 3 «Оформите заказ», 4 «Нажмите «Оплатить»», 5 «Оплатите картой», 6 «Готово!» (сохранить ссылку, скачать файлы, печать — в учреждение). Под шагами — выноска «Сохраните ссылку на заказ» и «Остались вопросы?» (куратор в галерее, чат группы, подробная инструкция, вопросы-ответы).
- **KK-DEC-04.** Снимки шагов — живой режим текущего main с подменой API (Playwright `page.route`), телефон 390×844, плотность 2, WebP q80; данные условные («Детский сад «Солнышко»», «Звёздочки»), корзина на 1 250 ₽ — та же сумма, что на кадре ЮKassa. Страница ЮKassa — кадр из базы знаний (`p08`) без тестовой плашки. Шаги — 6 (одно действие на шаг): ребёнок, фото и формат, оформление, «Оплатить», карта на ЮKassa, «Готово».
- **KK-DEC-05.** Ссылка в приложении — общий компонент `BuyerGuideLink` с адресом в одной константе; открывается в новой вкладке, чтобы корзина и введённый email остались на месте. На странице заказа ведёт к шагу оплаты (`#oplata`).
- **KK-DEC-06.** Картинка превью `og:image` — абсолютный адрес `https://app.morefoto36.ru/kak-kupit/og.jpg` (мессенджеры не принимают относительный); при смене домена — правка одной строки.

- **KK-DEC-07.** Карточка кадра (`ProductSelector`): строка формата — название, цена, справа «+» (`Добавить в корзину: <формат>, <цена>`); добавленная печать — счётчик «− N +» (`changeCartLine`, 0 убирает строку), добавленный файл или комплект — «✓ В корзине» (нажатие убирает), покрытый комплектом или подарком — «В комплекте» / «В подарок». Под списком — «В корзине из этого кадра: N шт. · сумма» (`frame-lines.ts`). Одно изменение за раз: остальные кнопки ждут серверный расчёт. Подсказка J4 стоит под строкой электронного кадра. Выбор пользователя 13.10.2026 из трёх вариантов (подсказка с отметками, галочки с одной кнопкой).
- **KK-DEC-08.** «Сохранить в телефон» (`OrderLiveFiles`, `useLiveFiles.save`): только на сенсорном экране, где браузер принимает изображение в `navigator.share` (`share-files.ts`). Файл берётся по той же подписанной ссылке через `fetch` и передаётся в меню телефона; если нажатие «остыло» за время загрузки (`NotAllowedError`), файл остаётся готовым и меню открывается следующим нажатием («Фото готово — нажмите ещё раз»); закрытое меню — не ошибка. iPhone кладёт обычное скачивание в «Файлы», меню — в «Фото».

## Риски

- Мессенджеры кешируют превью ссылки: первая публикация должна идти уже с готовой картинкой.
- `X-Robots-Tag: noindex` на всём сайте не мешает превью Telegram/WhatsApp/VK, но проверяется после выкладки на stage.
- Магазин ЮKassa на stage может быть тестовым — гайд об этом не пишет (он для запуска); тексты оплаты общие.
- Меню «Поделиться» и скачивание внутри встроенных браузеров мессенджеров (Telegram, WhatsApp, MAX) на реальных телефонах стендом не проверяются — проверка на stage после выкладки.
- Демо-сценарии Cucumber (`e2e/steps`) устарели ещё с #189 (ищут выпадающий список продукции) и в гейт не входят — не обновляются.
