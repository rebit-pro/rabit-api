# Выравнивание электронной колонки PDF-ведомости

## Контекст и границы

В PDF разные группы с короткими и длинными списками кадров получают колонки разной ширины. Пользователь отметил это на снимке от 27.11.2026 и попросил вывести у купленных файлов один код кадра в формате `G004`. Выпуск #246 уже слит, для этой правки пользователь разрешил отдельный PR в `main` после E2E.

- Зафиксировать ширину колонок «Электронная версия» и «Итого» на весь PDF. Для ведомости без печати оставить под перечень большую часть строки. При наличии печати выделить место для форматов, сохранив одну позицию электронной колонки во всех группах документа. Длинные слова переносятся по ширине заданных колонок.
- В компактном списке оставить исходное имя файла, код кадра в скобках и множитель для количества больше одного. Сохранить справочные сведения о заказе и детализацию печати и комплектов.
- Скорректировать формулировку в руководстве по отчётам и ожидание существующего теста на совпадение имён файлов.
- Границы поставки — разметка PDF, тест и руководство. Суммы, данные API, web-ведомость, merge и выкатка вне задачи. По поручению проводится E2E.

## Зависимости и риски

База `aff4b10540202062e09341cf4705169de967b8a4`, ветка `codex/ops-sales-report-pdf-alignment`. Результат определяют реальные размеры в mPDF. Проверить группы с разными именами, количеством файлов и печатными форматами, повтор заголовков на следующей странице и сохранение путей ZIP. Внешняя песочница ЮKassa отключена. Подготовка двух изолированных стендов выполняется последовательно для экономии памяти.
