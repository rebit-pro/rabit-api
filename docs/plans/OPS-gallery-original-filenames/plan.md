Этап 2 одобренного плана встречи 07.11.2026: покупатель видит все фото группы, исходное имя загруженного файла с ведущими нулями и расширением; прежний `?child=` ничего не скрывает. ## Scope

- Выдача исходного `UF_FILENAME` через Media → DTO → JSON галереи.
- Имя на карточке и в просмотре, читаемые переносы длинных имён на телефоне, экранирование обычной интерполяцией Vue.
- Удаление поиска/кнопок серий/фильтрации; все фото в устойчивом порядке, назначения одного ребёнка рядом, порядок снимков ребёнка сохранён.
- Прямой кадр, соседние кадры, короткие/длинные ссылки, корзина, покупка и MAX сохраняют текущие идентификаторы.
- Актуальные пояснения в parent/faq/помощи и подготовленные E2E-сценарии без запуска.

Вне scope: изменения этапа 1/PR #235, новые правила продаж/цен, отчёты, архивы и папки Nшт (этап 4), исходные байты/хранилище/расширения файлов, закрытие или merge PR #231, создание PR/merge/deploy. Пользователь отдельно поручил commit/push этапа 2; независимое ревью коммита выполняется в другой сессии. Запрет на E2E и стенды сохраняется.

## Решения, зависимости и риски

- Media владеет исходным именем: читается `UF_FILENAME`, без вычисления по MIME, коду или пути хранения. БД/миграции/новые маршруты не нужны.
- Дополняется `GalleryAssignmentOutputDto` последним параметром `string $filename = ''`: существующие конструкторы совместимы, реальный mapper всегда передаёт имя. Поле используется HTTP-галереей сейчас и доступно потребителям `ChildPhotosInterface` для следующих этапов. DTO `OriginalFileOutputDto` из незамерженных исправлений PR #235 не меняется.
- `GalleryPhoto.filename` optional для совместимости старого API/данных; пока имени нет, UI показывает существующий код. Demo передаёт настоящее сохранённое `ManagedPhoto.filename`, не выдумывает имя.
- `useGallery` не читает `query.child`; URL сохраняется для совместимости коротких ссылок. `query.photo` по assignmentId/id продолжает работать.
- Порядок задаёт чистая функция `galleryPhotos`: группы по длине/значению кода, фото внутри группы в порядке поставщика; входные данные не мутируются, общие фото с разными assignmentId не объединяются.
- Дизайн существующий: GalleryScreen составляет экран, GalleryGrid показывает карточки, PhotoViewer — кадр и ProductSelector, useGallery — загрузка/навигация. Новая библиотека/компонентный слой не вводится.
- Возможный последующий merge PR #231 требует повторной проверки удаления фильтра; самостоятельно PR не закрывать. Независимый review и реальная visual/HTTP/E2E приёмка остаются до merge.

## Критерии и тест-кейсы

1. **T08-NAME.** Готовая запись `IMG_00217.JPEG`/`0007.webp`/кириллическое имя → mapper и JSON → точное имя без изменения регистра/расширения и приватного пути. Legacy-конструктор DTO без имени допустим. Команда: Docker PHP 8.4 `phpunit --testsuite=unit --filter 'ChildPhotosTest|GalleryFilenameTest'`.
2. **T08-ALL.** Входные дети AA/B/A/Z/AB с несколькими снимками и общим photoId при разных assignmentId → полный список A/B/Z/AA/AB, прежний порядок снимков, дубли назначений сохранены, вход не мутирован. Команда: `npm --prefix frontend run test:ui` (включает gallery unit).
3. **T08-URL.** Старая короткая/длинная ссылка с `?child=ZZ999&photo=<assignmentId>` → все кадры видны, прямой кадр открывается после reload, просмотр закрывается с возвратом фокуса, соседние кадры доступны. Команды: `typecheck:e2e`, до merge отдельным исполнителем `make test-e2e` по docs/waves/a8/README.md; этот ход без E2E.
4. **T03.** Добавление продукции выбранного кадра, быстрый переход к соседнему и восстановление корзины сохраняют assignmentId. Команды: `npm --prefix frontend run test:commerce`, PHP Commerce unit; реальный E2E отдельным исполнителем до merge.
5. **T08-UI.** Карточка/просмотр с длинным именем, desktop/mobile, никакого поиска серий; короткий URL и MAX работают. Команды: frontend lint/stylelint/typecheck/build, подготовленный real E2E; визуальная проверка до merge, здесь не запускается.
6. **T08-DOC.** parent/faq/помощь не предлагают удалённый фильтр; старые anchors сохранены. Команда: адресное чтение/поиск, `git diff --check`; визуальные иллюстрации требуют отдельной актуализации по настоящему E2E.

Планируемые проверки: полный PHP unit в контейнере с исходниками этого worktree и общим vendor ro, phplint, PHPStan, CS Fixer только собственных PHP-файлов; frontend lint, lint:styles, typecheck, typecheck:e2e, test:ui, test:commerce, build-only. Зависимости переиспользуются только как vendor/node_modules; код первого worktree не попадает в автозагрузку тестируемого дерева.
