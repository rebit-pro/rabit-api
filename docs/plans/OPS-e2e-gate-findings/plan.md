## Цель и контекст

После #58 гейт `make test-e2e` занимает около 4 минут. Во время работы найдено семь проблем и резервов (#61):

1. Ресурсы прерванных прогонов остаются в Docker, а `make e2e-down` без `state.json` их не удалит.
2. Xdebug в development-образах загружается дважды и на каждый запрос пытается подключиться к отладчику.
3. `zzzz-links` ждёт смены минуты до 60 с — это до трети группы B.
4. Контейнеры пишут в checkout файлы от root; worktree не удаляется без sudo.
5. Таймаут браузерного этапа 900 с меньше собственного таймаута opt-in bench (45 мин).
6. `tools/__pycache__/` не игнорируется.
7. Резервы ускорения, для которых нужны замеры и решение.

Цель — закрыть пункты 1–6 без ослабления гейта, по пунктам с решением пользователя подготовить варианты.

## Scope

1. **Очистка брошенных стендов.**
   - Каждый ресурс запуска получает, кроме `rabit.browser_e2e=<run id>`, метки `rabit.browser_e2e.report=<абсолютный путь отчёта>` и `rabit.browser_e2e.owner=<host>:<pid namespace>:<pid>:<start time>`.
   - Новое действие `run-browser-e2e.py prune` и цель `make e2e-prune`. По умолчанию — только отчёт (dry-run). Удаление — `make e2e-prune E2E_PRUNE_APPLY=1`.
   - Отбор строго по метке `rabit.browser_e2e`, имя ресурса обязано начинаться с `<run id>-`, run id — `rabit-e2e-<12 hex>`.
   - Запуск удаляется, только если одновременно:
     - ни один его контейнер не работает (`running`, `restarting`, `paused` и прочие, кроме `created`, `exited`, `dead`);
     - процесс-владелец не жив: тот же host и PID namespace, а PID с тем же временем старта отсутствует. Если владельца проверить нельзя (другой host или namespace, старые ресурсы без метки), решает только возраст;
     - самый новый ресурс запуска старше `E2E_PRUNE_MIN_AGE_HOURS` (по умолчанию 2 ч).
   - Контейнеры удаляются `docker rm` без `--force`: Docker сам откажет, если контейнер успел запуститься. Затем сети и тома.
   - Общие тома `rabit-e2e-npm-cache`, `rabit-e2e-phpstan-cache` меток не имеют и в отбор не попадают.
2. **Xdebug.** Из `api/docker/development/php/conf.d/xdebug.ini` убираются `zend_extension=xdebug.so` (расширение уже включает `docker-php-ext-enable`) и запись лога в несуществующий `/app/log`. Режим по умолчанию — `off` (вариант A, решение пользователя 2026-09-25); отладка — переменной `XDEBUG_MODE`.
3. **`zzzz-links` без ожидания минуты.** Сценарий F2 делится на два файла одной группы B:
   - `z-links-preparation.spec.ts` — первым в группе B: создание группы, кадр, назначения, проверки `REVISION_CONFLICT`/`SIGNATURE_CONFLICT`/`REVIEW_REQUIRED`, подготовка через экран, переименование, `SIGNATURE_CONFLICT`/`LINK_NOT_PREPARED`, повторная подготовка. Итог (ID группы и съёмки, суффикс, минута подготовки, токен галереи, подпись) пишется в `var/f2-links.json`.
   - `zzzz-links.spec.ts` — на прежнем месте: проверка, что подготовка не сбита промежуточными спеками, head/teacher/curator, передача через экран, повтор по ключу, `SENT_AT_BEFORE_LINK`, коррекция на минуту подготовки, история `prepared, prepared, transmitted, corrected`, чужой учитель.
   - Между частями выполняются `zz-avatar` и `zzz-handoff` (по отчётам последних прогонов 32–53 с), а ожидание стоит непосредственно перед вводом даты передачи, после входов head и teacher. Poll остаётся страховкой и обычно возвращается сразу.
   - `verify-links.php` требует оба файла в одной группе.
4. **Файлы root.** В конце `stop()` одноразовый контейнер возвращает текущему пользователю владельца файлов `frontend/` (кроме `node_modules`) и папки запуска `api/var/e2e/<run>`, которые ему не принадлежат. Выполняется при `run`, `down` и при очистке после ошибки/отмены.
5. **Таймаут bench.** Группа, в которую входит `zz-media-bench`, при `E2E_MEDIA_BENCH` получает таймаут браузерного этапа 900 + 2700 = 3600 с; остальные группы — прежние 900 с.
6. **`.gitignore`**: `__pycache__/`.
7. **Резервы** — только перечень и решение пользователя, без изменений (нужны замеры на целевой машине).

## Зависимости и решения

- Зависимостей по графу волн нет. Нужен `main` с runner #58 (есть с `2cc2360`).
- **Пункт 1.** Правило issue «`state.json` отсутствует или все контейнеры остановлены» усилено: работающий контейнер защищает запуск всегда, даже без `state.json`. Дополнительно защищают живой владелец и минимальный возраст — это закрывает окно `start()`, когда сети и тома уже созданы, а контейнеров ещё нет (сборка образов до 30 мин).
- **Пункт 3.** Рассмотрены варианты:
  - управляемое время сервера — потребовало бы тестовый clock в продуктовом коде и сдвинуло бы время для всех спеков стенда; отклонено;
  - перенос второй части в конец группы B (предложение issue) — после `zzzz-storefront`/`zzzzz-orders` меняется глобальный каталог и условия. Отпечаток продаж группы (`salesFingerprint`) входит в подпись готовности, подготовка сбрасывается, а quote упирается в #51. Отклонено;
  - перенос первой части в начало группы B — выбран. `zz-avatar` и `zzz-handoff` не меняют каталог, условия, кадры и назначения группы F2 (handoff добавляет учителю свою группу с `replaceAssignments: false` и выбирает опции по именам с суффиксом).
  - Проверяемые свойства не меняются: коды ошибок, коррекция ровно на минуту подготовки, история и `verify-links` прежние. Минута подготовки по-прежнему берётся из `history[0].at` реального сервера.
- **Пункт 4.** Выбран `chown` в конце `stop()`, а не `--user` для node-контейнеров: общий том `rabit-e2e-npm-cache` уже заполнен root-файлами и параллельно используется сессиями со старым runner; свежие тома `node_modules` принадлежат root; пользователь образа Playwright — UID 1001, а не 1000. Переход на `--user` потребовал бы отдельного кеша и подготовки томов, а без полного gate его не проверить.
- **Пункт 2, режим Xdebug по умолчанию — решение пользователя 2026-09-25: вариант A.** Реализовано: `xdebug.mode=off` в ini, `XDEBUG_MODE: ${XDEBUG_MODE:-off}` в общем окружении CLI-сервисов и у `api-php-fpm`, `XDEBUG_MODE=off` с подсказкой в `.env.example`; `api-php-cli` по-прежнему явно `off`. Рассматривались варианты:
  - A. `xdebug.mode=off` в ini; отладка — `XDEBUG_MODE=debug,develop` в `.env`/compose (например, `XDEBUG_MODE: ${XDEBUG_MODE:-off}` у `api-php-fpm`). Нет накладных расходов и попыток подключения, отладка включается одной переменной. Рекомендуется.
  - B. `mode=develop,debug` + `start_with_request=trigger`: подключение только по `XDEBUG_TRIGGER` (cookie/параметр/переменная). Попыток подключения без триггера нет, но режим `develop` замедляет каждый запрос.
  - C. Оставить `start_with_request=yes`: локальная отладка без действий, stage и E2E продолжают задавать `XDEBUG_MODE=off`.
- **Решение пользователя — пункт 7.** Третий стенд, перенос `zz-media` в B, `--performance-schema=OFF`/меньший buffer pool MySQL, готовый `node_modules` — только после замеров на целевой машине.

## Риски и ограничения

- Разделение F2 не проверено полным gate до ревью. Риск: промежуточный спек сбивает подготовку группы F2. Вторая часть сначала сверяет подпись и `prepared` с сохранёнными и падает с понятным сообщением.
- В худшем случае (подготовка в самом начале минуты и быстрые промежуточные спеки) остаточное ожидание — до ~15 с вместо 60.
- Состав гейта: 78 сценариев вместо 77 (F2 — два теста).
- Проверка владельца по PID работает только в том же PID namespace (WSL-дистрибутив). В другом решает возраст.
- `chown` не выполнится, если процесс убит SIGKILL; тогда файлы root остаются до следующего `run`/`down` в этом checkout, который их исправит.
- Изменение `xdebug.ini` действует только после пересборки образа; существующие теги не пересобираются.
