# OPS: миниатюры в PDF отчёта E10 через imageVars mpdf

## Цель

PDF отчёта группы (COM-16) собирается на настоящих данных с миниатюрами детей.

## Контекст

- Выкладка E10 (PR #221, main 8e3855e) на stage 25.10.2026, релиз `main-20261025130650-8e3855e`.
- DI smoke в FPM под `www-data` на реальных данных:
  - отчёт и PDF уровня «все» — OK (46 КБ, 0,7 с);
  - PDF группы с 12 миниатюрами — `SalesReportException`: `The HTML code size is larger than pcre.backtrack_limit 100000`.
- Причина: `SalesReportHtml` встраивает каждую WebP-миниатюру в HTML как base64 data URI. Десяток настоящих превью (≈10–20 КБ каждое) делает HTML больше лимита PCRE, и mpdf отказывается разбирать его целиком. Тесты использовали крошечные «картинки» и этого не ловили.
- FPM возвращён на прежний релиз `main-20261017192004-65bd194`; frontend не переключался, раздел «Отчёты» на stage не появлялся.

## Решение

- **Writer:** миниатюры передаются mpdf через `$mpdf->imageVars['childN']`.
- **HTML:** ссылается на них `<img src="var:childN">`. Он остаётся маленьким при любом числе детей; тип картинки mpdf определяет по байтам (WebP по `RIFF`, JPEG, PNG).
- `SalesReportHtml::body()` принимает карту «ребёнок → имя переменной», а не байты. Помощник `mime()` удаляется.
- `pcre.backtrack_limit` не трогаем: без картинок строка таблицы занимает ≈0,4 КБ, лимит достигается лишь на сотнях строк одного уровня.
