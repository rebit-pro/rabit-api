## Правила количества, имён и коллизий

Решение зафиксировано до реализации на актуальном main и подтверждено исходниками/AST. Старый формат использует entry без расширения; новый формат хранит полный entry и явный layoutVersion=2.

1. Ключ задания — группа + идентичность продукции + идентичность фото. Число отпечатков — сумма `quantity * printCount` всех допустимых оплаченных строк этого ключа в текущей версии. Общий кадр разных детей не дедуплицирует оплаченные экземпляры; сохраняется связь со всеми строками.
2. Один отпечаток — файл непосредственно в папке продукции; N > 1 — один файл в `Nшт/`. Не создавать `1шт`, `_xN` или вторую копию задания в корне продукции.
3. Безопасный исходный basename сохраняется побайтно, включая ведущие нули, регистр и расширение; байты оригинала не преобразуются. Нельзя подменять имя кодом кадра или именем объекта хранения.
4. Папки продукции назначаются в лексикографическом порядке productId. Название выбирается детерминированно из снимков одного товара, очищается только имя папки; при коллизии NFC + case folding к нему добавляется полный productId, при необходимости числовой индекс. Разные товары не объединяются по формату. Коллизии basename разных фото проверяются внутри продукции и количества; все участники получают `<продукция>/[Nшт/]_фото/<полный photoId>/<исходный basename>`. Корневое имя файла `состав.csv` зарезервировано и не может быть папкой продукции. Имена `_фото` и `Nшт` резервируются как каталоги и тоже помещаются в `_фото/<id>/`. Так исключаются конфликты файла с каталогом без изменения basename; сравнение нормализуется, сами имена нет. ID допускают только безопасные ASCII-компоненты, полные пути ограничены 512 символами. Компоненты пути ограничены 255 байтами UTF-8: исходный basename при превышении отклоняется явно, а только генерируемое название папки продукции сокращается с резервом для ID-суффикса.
5. Небезопасное имя не исправлять молча. Если имя нельзя безопасно сохранить (разделитель пути, traversal, управляющие символы, несовместимое зарезервированное имя либо превышение ограничения), сборка завершается явной ошибкой без статуса готовности и выдачи неполного ZIP. Не выдумывать исходное имя при его отсутствии.
6. CSV содержит фактический относительный путь задания и трассировку всех исходных строк. ZIP и CSV строятся по одному зафиксированному составу. В формате 2 к прежним колонкам добавляются ID строки/заказа/фото/продукции и общее число отпечатков файла. Исходный basename содержится в полном пути, отдельная избыточная колонка имени не нужна. Папка продукции получает безопасный префикс, если её начало могло бы быть формулой Excel: это сохраняет буквальное значение пути в CSV без апострофа. Каждая исходная строка остаётся отдельной строкой CSV, несколько строк могут указывать на один агрегированный entry. Исторический CSV формата 1 не меняется.

### Данные, совместимость и отказ

Сначала применяется аддитивная миграция, затем код. Старые записи получают layoutVersion=1; их состав, ссылки, сроки и дополнения не переписываются. Новые снимки получают 2. Builder не пересчитывает сохранённые entry при повторе/перевыпуске, отдельное дополнение содержит только ещё не включённые строки. Новый код не выполняет deployment/миграцию на рабочей БД. После появления v2 обратная миграция и возврат к старому builder/CSV запрещены: восстанавливать работоспособность совместимым кодом, не изменяя сохранённые версии.

Неизвестный photoId или отсутствующее имя не заменяются storage filename: снимок явно отклоняется ORIGINAL_MISSING. Небезопасный basename отклоняется UNSAFE_FILENAME (409), существующие строки/версии не резервируются; после исправления источника снимок повторяется. Если имя известно, но OriginalFiles не вернул готовый оригинал, прежняя версия FAILED/ORIGINAL_MISSING сохраняется. Физическая ошибка чтения/записи остаётся в существующем ограниченном retry. ZIP публикуется атомарным AtomicZipWriter; изображения не загружаются целиком в PHP-память. Права, 14 дней хранения, поколения ссылок и +1 час не меняются.

Для R1 постоянный курсор сохраняется перед первой отклонённой группой, включая успешные группы после неё: после исправления имени cron повторяет исходный snapshot автоматически. Успешные соседние группы могут оказаться впереди курсора, но `firstOnly`, сохранённые версии и уникальные ключи не дают повторно учесть их строки. Локальный обход через страницы нужен и при limit=1; отказы и уже созданные версии не расходуют лимит новых версий. Память ограничена страницей; при длительно неисправленном имени cron повторно читает хвост закрытых групп от блокера до лимита новых версий/границы cutoff. Это осознанная цена восстановления без отдельной очереди/нового хранения. Неизвестные ошибки источников/хранилища не маскируются под ошибку имени.
