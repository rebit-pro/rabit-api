# Выбор кадра и доставка электронных файлов

## Цель и контекст

Этап 1 утверждённого плана `docs/plans/OPS-telemos-20261107-prompt/artifacts/implementation-stages.md`. Нужно установить, где расходятся выбранный покупателем кадр, строки заказа и доставленные файлы, исправить подтверждённый дефект и сохранить правила J4, комплектов, подарков и дедупликации.

В записи показаны две позиции с кодом Z004; это не доказывает ошибку почты или фактический выбор другого кадра. PR #231 открыт и относится к галерее, issue #233 открыт и относится к другому почтовому инциденту.

## Scope

- Путь выбора кадра: галерея → ProductSelector → корзина/quote → checkout → сохранённая строка заказа.
- Путь доставки: права → оригиналы → план вложений и ссылок → части письма → очередь и повтор.
- Адресные исправления, регрессионные тесты и пояснение в руководстве для покупателя.

Вне scope: этапы 2–8, фильтр серий и исходные имена галереи, новые отчёты и архивы, резервный SMTP, реальные письма покупателям, merge и deployment.

## Зависимости, решения и риски

- База: удалённый `main` `6564f88c6c0519bbcc02d026f99b9174bbecdf20`, проверен через `gh api` 07.11.2026; ветка `codex/ops-order-photo-delivery` создана от этого SHA. Перед PR повторно сверить актуальный main.
- Не переносить код открытого PR #231 и не трактовать issue #233 как причину показанного заказа.
- Все проверки с БД выполнять только в изолированной среде; боевые письма не отправлять.
- Причину исходной жалобы считать установленной лишь при наблюдаемом первом расхождении или воспроизведении. Если её нет, ограничить изменения полезными регрессионными проверками и явно оставить инцидент неразрешённым.
- Подтверждённый по коду самостоятельный дефект доставки: `OrderFileAccess` пропускает отсутствующий оригинал из уже положенных заказу кадров и помечает доступный остаток как полный. Исправление: отдельное состояние `incomplete` для заказа с положенными кадрами без всех оригиналов; не выдавать частичный набор, оставить автоматическое письмо в `held` до восстановления оригинала и показать покупателю понятное состояние. Заказ без положенных кадров сохраняет `empty` и письмо со ссылкой. Не раскрывать в API серверные пути или внутренние ошибки хранения.
- Media возвращает запись готового оригинала по метаданным, даже если файл уже отсутствует в приватном хранилище. Добавить проверку существования через порт хранилища Media; Files получит неполный набор по действующему межмодульному контракту. Проверка не отменяет повторную проверку файла при фактической отправке/скачивании из-за гонки между проверкой и чтением.
- Reviewer не запускает E2E. Обязательный реальный HTTP/браузерный E2E и визуальную проверку перед merge выполняет пользователь с другой моделью.

## Состав решения

- `morefoto.media`: внутренний порт `PrivatePhotoStorageInterface` получает `exists(string $relativePath): bool`; `LocalPrivatePhotoStorage` проверяет физический файл, а `OriginalFiles` не возвращает исчезнувший оригинал. Публичный контракт `OriginalFilesInterface` не меняется.
- `morefoto.files`: `OrderFileAccess` сопоставляет весь положенный заказу состав с найденными оригиналами. Новое API-состояние `incomplete` возвращает пустые `items`, `canDownload: false`; запрос скачивания получает действующий `FILES_UNAVAILABLE` (409). Автоматическое письмо остаётся `held` и при следующем dispatch планируется после восстановления полного состава.
- `frontend`: `FilesState` и `OrderLiveFiles` показывают покупателю сообщение для `incomplete`; backend и frontend выпускаются совместно. `guide/parent` уточняет права на копию печатного кадра, части письма и ссылки на крупные файлы.
- Данные/совместимость: миграций и новых маршрутов нет. Исторические письма не изменяются; одновременное исчезновение файла после проверки остаётся возможным. Проверки: Media/Files/Commerce unit, полный PHPUnit, PHPStan, frontend lint/типы/unit/build; до merge — реальный `make test-e2e` T01–T04 на изолированной БД и визуальная desktop/mobile проверка.

## Критерии приёмки

Печать A и digital B дают в заказе и доступе два разных photoId и два файла. Печать A и digital A дают один файл с двумя основаниями права, а несколько форматов печати не размножают его. Смена кадра и восстановленная корзина сохраняют фактически выбранный assignmentId. Части письма и крупные файлы не пропадают молча, повтор не дублирует уже учтённые части. Непроведённые E2E остаются явно обозначенными.

## Тест-кейсы

1. **T01.** Предусловие: обезличенная группа с разными A/B и оплаченным заказом «печать A + digital B». Действие: проверить quote, сохранённые строки, права и доставку. Ожидание: два разных photoId и оба оригинала. Команды: адресные Commerce/Files PHPUnit; `npm --prefix frontend run test:commerce`; перед merge — `make test-e2e` в изолированной БД отдельным исполнителем.
2. **T02.** Предусловие: A куплен в печати нескольких форматов/количеств и отдельно как digital. Действие: собрать права и письмо. Ожидание: один цифровой файл A, без потери иных оплаченных прав. Команды: адресные Commerce/Files PHPUnit; перед merge — `make test-e2e` отдельным исполнителем.
3. **T03.** Предусловие: минимум два кадра, доступна сохранённая корзина. Действие: быстро переключить кадр и добавить товар, перезагрузить и оформить. Ожидание: assignmentId выбранного кадра остаётся в quote и заказе. Команды: `npm --prefix frontend run test:commerce`; адресные Commerce PHPUnit; перед merge — `make test-e2e` отдельным исполнителем.
4. **T04.** Предусловие: несколько частей письма, файл больше порога ссылки, контролируемый сбой между частями. Действие: выполнить доставку и повтор. Ожидание: все файлы учтены, статус отражает фактические части, пропуска нет. Команды: адресные Files PHPUnit; интеграция в изолированной БД; перед merge — `make test-e2e` отдельным исполнителем.

Планируемый общий gate после изменения кода: `make lint`, `make analyze`, адресные PHPUnit через `docker compose run --rm api-php-cli composer test -- --testsuite=unit --filter='…'`; при изменении Vue/TS — `npm --prefix frontend run lint`, `npm --prefix frontend run typecheck`, `npm --prefix frontend run test:commerce`, `npm --prefix frontend run build-only`. PHP CS Fixer — только по изменённым PHP-файлам.
