# Один ZIP для съёмки учреждения и общая галерея с выбором группы

**Цель.** Организатор открывает карточку школы или детского сада, выбирает съёмку и загружает один архив сразу для всех её классов или групп. Родитель получает один адрес, видит плитки с обложками и по названию выбирает свою группу.

**Согласованная граница.** Общая ссылка открывает группы **одной выбранной съёмки учреждения**. У весенней и осенней съёмок одной школы разные адреса, даже если в обеих есть «1А». План одобрен пользователем 18.11.2026. Реализация и исправления после ревью находятся в ветке `codex/ops-institution-zip-import`.

## Загрузка архива

1. В карточке учреждения появляется действие **«Загрузить ZIP по группам»**. При одной съёмке её название и дата уже в форме. При нескольких организатор выбирает нужную. Если съёмок ещё нет, здесь же доступна штатная форма «Новая съёмка». Выбрать группу перед загрузкой не требуется.
2. Первая папка — новая группа или класс выбранной съёмки, вторая — серия ребёнка. Пример создаёт новые «1А» и «1Б», даже если в учреждении или этой съёмке уже есть одноимённые группы. У каждого класса своя серия `A`.

   ```text
   Весна.zip
   ├── 1А/
   │   ├── A/0001.jpg
   │   ├── B/0002.jpg
   │   └── GROUP-1/класс.jpg
   └── 1Б/
       ├── A/0003.jpg
       └── B/0004.jpg
   ```

3. До первой записи показать дерево групп, серий и кадров, причины пропусков и выбор корня при неоднозначной вложенности. Поддержать одну внешнюю папку-обёртку и ZIP с единственной группой. Отмена на этом шаге сохраняет исходные данные.
4. Для каждой непустой папки создать отдельную обычную группу выбранной съёмки с названием папки. Источник состава — архив. Для идентичного ZIP, выбранного тем же организатором в той же съёмке с тем же корнем и кодами серий, использовать группы из квитанции этого импорта, если все они существуют в выбранной съёмке. Иначе показать явное сообщение и предложить начать новый импорт: новые группы для всех папок, без изменения сохранившихся групп. Другой ZIP создаёт свои группы.
5. Папки A, B, AA задают коды серий. Для произвольного имени предложить свободный код и дать отредактировать до отправки. Групповые кадры GROUP* получают все серии этой папки. Неподдерживаемые файлы, пустые папки, дубли путей и ошибки вложенности перечислить в сверке.
6. После подтверждения отправлять оригиналы штатной очередью. В общем итоге и по каждой группе показывать, сколько кадров принято, сколько превью готово, какие файлы пропущены и где требуется действие. После разрыва связи повторный выбор того же ZIP продолжает работу с уже найденными ID. Изменившийся архив проходит новую сверку. Организатор может повторить проблемные файлы, сохранив успешные группы.

## Передача ссылки

- В **«Ссылках и сроках»** основная строка соответствует съёмке. Заголовок колонки — **«Съёмка»**, первая строка ячейки — **«Весенняя фотосессия»**, вторая — **«Школа № 12»**. Вложенные строки показывают названия групп, их готовность, даты и действия. При разных сроках выводить их у соответствующих групп. Сохранить поиск по учреждению, съёмке и группе, фильтры, сортировку и переход по существующим ссылкам кабинета с выбранной группой.
- Основное действие строки — **«Скопировать общую ссылку»**. При копировании нескольких съёмок выдавать по одному подписанному адресу на съёмку. История и индивидуальная передача остаются доступны в строке группы. Сотруднику с назначением только на отдельную группу доступна её прямая ссылка. Право на общую ссылку проверяется сервером по всей съёмке.
- **«Отметить передачу»** показывает, какие группы готовы, какие уже открыты, каким назначено открытие и какие ещё требуют проверки. Одно подтверждение передаёт показанные готовые группы действующими командами Handoff. Для открытия по расписанию отдельно фиксируется факт отправки. При частичном успехе показывать итог по каждой группе и повторять только незавершённые действия. Чтение ZIP, загрузка, подготовка и копирование адреса сами по себе продажи не запускают.
- Родитель сначала видит **плитки групп**. Плитка содержит читаемое название и миниатюру выбранной обложки. Если обложку ещё не назначили, показывается первый доступный размеченный кадр этой группы в устойчивом порядке. При отсутствии миниатюры использовать нейтральную картинку. Нажатие открывает действующую галерею группы с её сериями, просмотром и покупкой. Переход «К группам» возвращает в ту же съёмку. Это работает и для одной группы.
- Состав плиток — обычные группы выбранной съёмки с действующей групповой ссылкой и разрешённым просмотром. До первого открытия общая страница показывает «Фотографии ещё готовятся». При частичной готовности открытые группы уже видны, остальные появляются по этой же ссылке после открытия. Истечение срока покупки обрабатывается по календарю каждой группы, включая действующее право просмотра. Служебные группы сотрудников и съёмки других дат в подборку не входят.

## Исходная версия

- В Organization группа принадлежит съёмке, съёмка — учреждению. Одноимённые группы разных съёмок допустимы. В проекте уже есть выбор съёмки и создание обычной группы со страницы учреждения. Операция создания поддерживает ключ повтора, но сама по себе не ищет группу по имени. [Контракт структуры](../../waves/c3/README.md) · [Создание группы](../../../api/public/local/modules/morefoto.organization/lib/Application/Structure/UseCase/SaveGroupUseCase.php)
- До этой задачи ZIP загружали для одной выбранной группы. Браузер читает оглавление, распаковывает файлы по мере отправки и передаёт `groupId` и `childCodes` существующему upload API. Действуют JPEG/PNG/WebP, 25 МиБ и 40 Мп на кадр, две параллельные отправки и лимит очередной партии 2 000 кадров. [Разбор ZIP](../../../frontend/src/modules/morefoto/photos/archive.ts) · [Очередь](../../../frontend/src/modules/morefoto/photos/composables/usePhotoQueue.ts) · [Лимиты](../../../frontend/src/modules/morefoto/photos/rules.ts)
- Media считает дубликатом одинаковое содержимое в одной съёмке. Если оригинал принадлежит другой группе, привязка серий к нему вернёт пустой список. В полном импорте такой результат следует показать как конфликт конкретного файла, исключить из числа успешно доставленных и из отметок возобновления. [Регистрация кадра](../../../api/public/local/modules/morefoto.media/lib/Domain/Photo/Repository/PhotoRepository.php) · [Привязка серий](../../../api/public/local/modules/morefoto.media/lib/Application/Photo/Service/UploadChildAssignment.php)
- Публичный адрес `/g/:token` ведёт в одну группу. Media проверяет ключ и готовность просмотра. Handoff проверяет материалы и условия продаж перед передачей. В кабинете список уже получает `shootName`, `institutionName` и название группы. ### HTTP-контракты

Пути таблицы даны после `/api/v1`. Новые контроллеры принимают типизированный request DTO. Чтение запроса, Bearer, обработка ошибок и HTTP-логирование остаются в общей обвязке.

| Запрос | Вход, результат и ошибки |
| --- | --- |
| Существующие `GET /institutions/{id}`, `GET /institutions/{id}/shoots`, `GET /shoots/{id}` | Данные карточки учреждения. Мастер выбирает съёмку из списка учреждения, состав новых групп читает из оглавления ZIP. |
| Новый `POST /institutions/{institution_id}/shoots/{shoot_id}/import-groups` | `Idempotency-Key`, строковый список названий папок `groups`. Результат `groupIds` соответствует порядку папок. Для нового ключа создаются новые группы. Повтор ключа с тем же телом возвращает их ID, с другим телом — 409. Если хотя бы одна группа квитанции отсутствует в выбранной съёмке — 409 `IMPORT_GROUPS_UNAVAILABLE`, без записи новых групп и без возврата успешного результата. Неправильная форма — 422, права и область — 403/404. |
| Существующий `POST /shoots/{shoot_id}/photos` | По одному оригиналу с `groupId` и кодами именно этой группы. Статус превью и результат назначения отслеживаются раздельно. При `GROUP_MEDIA_LOCKED` остановить затронутую группу и предложить перечитать её состояние. |
| Новые `POST /shoots/{shoot_id}/gallery-link` и `GET /shoots/{shoot_id}/gallery-link` | Организатор выпускает или повторно получает тот же адрес после подготовки хотя бы одной обычной группы. GET читает существующий адрес. Чтение доступно сотруднику с правом чтения всей съёмки, передача — с правом передачи и полной областью. Ответ содержит `galleryPath`. 409 при отсутствии подготовленных групп, 404 для отсутствующего адреса при чтении или ресурса вне области. |
| Существующие команды `POST /groups/{id}/link-preparations`, `…/link-transmissions`, `…/manual-link-deliveries` | Интерфейс передаёт актуальные revision/signature и ключ повтора на группу. Подготовка требует действующих подтверждений организатора. При расписании факт отправки и фактическое открытие разделены. |
| Новый `GET /public/galleries/shoots/{key}` для страницы `/g/s/{key}` | Названия съёмки и учреждения, состояние и плитки с `name`, `groupPath`, `coverUrl` (может быть null). Действующий путь группы открывается по короткой ссылке или поддерживаемому старому адресу. Неизвестный или отозванный ключ — 404. До открытия — 200 с состоянием ожидания. |
| Новый `GET /public/galleries/shoots/{key}/groups/{group_id}/cover` | Только разрешённая миниатюра. При каждом чтении проверить общий ключ, принадлежность, календарь, действующую групповую ссылку и доступность самого кадра. Чужая или недоступная обложка — 404. |

### Данные, частичный сбой и совместимость

- Подтверждение групп — одна транзакция Organization. Квитанция существующего журнала хранит ID созданных групп для данного организатора, съёмки и ключа импорта. Браузер вычисляет ключ по содержимому ZIP, выбранной съёмке, корню и подтверждённым кодам серий. Смена съёмки, архива или настроек создаёт независимый импорт.
- При повторе квитанции `StructureRepository::importedGroupsExist(int $shootId, array $groupIds): bool` проверяет весь набор одной SQL-выборкой под действующими блокировками сценария. Удалённые ID не восстанавливаются и старая квитанция не переписывается. После явного действия «Начать новый импорт» браузер выбирает следующий стабильный ключ от предыдущей попытки и сохраняет его в области пользователя/учреждения/съёмки/архива/кодовой схемы. Потеря ответа или обновление страницы повторяют новый ключ; локальные отметки старых ID не учитываются. Повтор из другого браузера также не должен создавать две одинаковые попытки с одним исходным ключом. Новый импорт сохраняет существующие группы; совпадение содержимого с ними остаётся явным межгрупповым конфликтом по действующему правилу Media.
- Сеть и обработка превью выполняются после подтверждения структуры. Остановка импорта сохраняет созданные группы и принятые кадры. Прогресс привязан к пользователю, учреждению, съёмке, ID группы, соответствию серии, исходному пути и содержимому записи. Имени и размера ZIP недостаточно для пропуска файла после его замены. После сбоя опираться на ответ Media и готовность канонического кадра. При смене учреждения или съёмки отменять ожидающие операции старого экрана.
- Для архива на всё учреждение обрабатывать и распаковывать ограниченную порцию за раз с общим лимитом параллелизма. Лимит партии 2 000 не должен вынуждать вручную делить ZIP. Проверять фактический размер распаковки, пути и формат. В поле `childCodes` помещаются до 100 кодов. Если групповой снимок предназначен большему числу детей одной группы, оставшиеся привязки выполнить штатной разметкой после готовности кадра. Не смешивать списки детей соседних классов.
- `usePhotoQueue` принимает необязательные настройки области импорта и getter незавершённой работы мастера. Route guard и beforeunload действуют с подтверждения структуры до завершения всех порций, включая ожидание превью, паузу и отправку оставшихся GROUP-привязок. Прежние режимы используют прежний критерий работы очереди. Lifecycle-проверки исполняют реальный composable в изолированном Vue-контексте; браузерный сценарий подтверждает защиту между порциями через реальный API.
- Общий ключ — случайный непрозрачный идентификатор. Запрашивать его в кабинете при явном действии с конкретной съёмкой. Для уже открытой группы со старым действующим ключом, от которого сохранился только хеш, подготовка общего адреса может выпустить копируемую групповую ссылку с сохранением старой. Группу с отозванным доступом исключать. Публичное чтение никогда не выдаёт новые ключи.
- Метаданные групп и идентификаторы доступных обложек читать пакетно. Браузер запрашивает миниатюры видимых плиток отдельно. Контекст возврата к плиткам хранить в сессии перехода, чтобы при копировании прямой ссылки группы родитель передавал адрес только этой группы. Сроки, отзыв и удаление проверять при следующем чтении, включая прямой запрос обложки. Использовать приватные заголовки кеша и действующие исключения журналирования путей `/g/` и `/api/v1/public/galleries/`.
- Выкладка предусматривает добавочную миграцию и backend до подключения frontend. При откате интерфейса сохраняются фотографии и рабочие групповые адреса. За границами задачи — постоянный справочник классов между учебными годами, печатные или электронные архивы купленных фотографий, массовая рассылка родителям и изменение правил покупки.

В кабинете видны название съёмки, учреждение и фактические сроки каждой группы. Съёмка другой даты недоступна по этому адресу. Ниже команды из корня рабочего дерева для этапа реализации.
