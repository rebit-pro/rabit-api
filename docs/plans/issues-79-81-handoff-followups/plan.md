# Issues #79 и #81 — хвосты ревью PR #78: обновление формы переноса и неопределённый исход F2

## Цель и контекст

Оба замечания — неблокирующие находки ревью PR #78 (F1, слит `2567178`). Их взяли в работу 2026-09-25 вместе с #77, #59 и #61; у каждой группы отдельная ветка и PR. Это issue-ветка, не волна: `docs/waves/graph.json` не меняется.

- [#79](https://github.com/rebit-pro/rabit-api/issues/79): «Загрузить актуальные данные» в подтверждении переноса считается успешным, даже если предпросмотр HND-10 упал. Форма пересобирается с пустой подписью, проверка набора пропадает из диалога, а ошибка остаётся за ним.
- [#81](https://github.com/rebit-pro/rabit-api/issues/81): на экране ссылок (F2) потеря ответа выдаётся за «Сервер не сохранил изменение», хотя сервер мог применить команду.

- Ветка: `codex/issues-79-81-handoff-followups`, worktree `/home/user/rabit-api-worktrees/issues-79-81-handoff-followups`.
- Base: `origin/main` `d92b4c4`.

## Установленные факты

- `useTransferPreview.load()` перехватывает ошибку HND-10, `settled()` всё равно завершается успешно. `StaffRequestsScreen.refreshWorkspace()` безусловно возвращает `true`.
- `useHandoffEditor.reset()` при `false` оставляет команду и показывает в диалоге «Не удалось загрузить актуальные данные…». Кнопка остаётся видна, потому что есть ошибка.
- `linkError()` не различает случай без HTTP-ответа и падает в общий текст «Сервер не сохранил изменение».
- После #78 черновик восстанавливается вместе с `Idempotency-Key`. Поэтому советы «Обновите страницу» и «Закройте форму и откройте её снова» в текстах ошибок F2 больше не дают новых данных и нового ключа. Это делает только «Загрузить актуальные данные»: `LinksScreen` пересобирает команду из перечитанной группы с новым ключом, revision и подписью.

## Решения

- **R1 (#79).** Правило `handoffRefreshSucceeded(action, previewError)` в `handoff/rules.ts`: для `confirm` обновление успешно только без ошибки предпросмотра, для остальных действий предпросмотр не нужен. `refreshWorkspace()` возвращает его результат.
- **R2 (#81).** Выбор текста ошибки F2 вынесен в чистую `linkErrorText()` (`handoff/link-errors.ts`), `linkError()` только разбирает ответ axios. Без ответа — «Ответ сервера не получен — изменение могло сохраниться…» и совет безопасного повтора или загрузки актуальных данных.
- **R3.** Тексты `REVISION_CONFLICT`, `SIGNATURE_CONFLICT`, `IDEMPOTENCY_CONFLICT` указывают на «Загрузите актуальные данные» вместо перезагрузки страницы и повторного открытия. Прочие 5xx — «Сервер не сохранил изменение. Повторите действие позже.».

## Критерии приёмки

- Для `confirm` при отказе HND-10 команда остаётся, в диалоге видна ошибка и кнопка повтора. Успешный повтор возвращает проверку набора.
- Для `submit`/`clarify` недоступный предпросмотр обновление не блокирует.
- Потеря ответа F2 сообщает о неопределённом исходе. Повтор неизменённой формы идёт с тем же ключом и получает replay.
- HTTP-ошибки валидации, прав и конфликтов сохраняют свои сообщения.
