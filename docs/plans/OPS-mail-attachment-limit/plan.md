# OPS: лимит вложений писем Bitrix под письма J5 (30 МБ)

## Цель

Поднять лимит вложений писем Bitrix `main.max_file_size` до 30 000 000 байт, чтобы письма J5 с оригиналами фото уходили. Решение владельца 17.10.2026: «Да, поднимаем до 30 МБ, делай PR».

## Контекст

- J5 (PR #209, 4fe304b) кладёт в письмо до 18 МБ оригиналов. Кадр крупнее 18 МБ идёт отдельно, если он не больше 20 МБ. После base64 самое большое письмо — 27 962 028 байт.
- При выкладке J5 17.10.2026 DI smoke показал на stage `main.max_file_size=20000000` — значение Bitrix по умолчанию (`main/default_option.php`, раздел «Почта»: «Максимальный размер файлов вложения в байтах (0 — без ограничений)»).
- Bitrix сравнивает сумму вложений после base64 с лимитом и молча подменяет лишнее заглушкой `.txt`. Транспорт J5 такие письма отклоняет (`attachment_limit`). При 20 000 000 не уходит любое письмо с фото больше ≈14,3 МБ, то есть уже два кадра по 8 МБ.
- 30 МБ — лимит письма у Яндекса (отправитель stage).
- Отправка писем заказа на stage выключена до #161. Изменение начнёт работать, когда её включат.

## Scope

- Миграция `Version20261017150001`:
  - `up`: если лимит больше 0 и меньше 30 000 000 — ставит 30 000 000; 0 («без ограничений») и больший лимит не трогает;
  - `down`: возвращает 20 000 000, только если стоит 30 000 000.
- Стенд E2E применяет миграцию (`prepare.php`). `verify-notification.php` проверяет: лимит 0 или не меньше самого большого письма J5 после base64.
- README J5 — шаг выкладки ссылается на миграцию.

### Вне scope

- Включение отправки писем — после #161.
- Лимиты вложений заявок с сайта: у них своя проверка размера файла.

## Риски

- Опция общая для всех писем Bitrix: письма с вложениями до 30 МБ станут возможны и для других отправителей. Сейчас вложения шлют только J5 и резервный email заявок, у которого свой лимит загрузки.
- Ящик получателя может принимать меньше 30 МБ. Тогда письмо получает отказ SMTP и статус `failed`, ссылка на заказ работает (J5).
