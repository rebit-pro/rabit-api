# L1 — архив оплаченной печати и ссылка для ручной передачи

## Цель

После окончания продаж печати группы (E7: отправка ссылки + 7 дней) система сама собирает ZIP оригиналов и CSV только по оплаченной печати. Организатор и куратор учреждения видят состояние в «Ссылках и сроках», скачивают архив или копируют ссылку для лаборатории (Сивма). Ссылка работает без входа, ограничена сроком и версией и может быть отозвана. Email лаборатории — не здесь (L3).

## Scope

1. **Модуль `morefoto.production`**: Domain (версия архива, строки снимка, правила состава и имён), Application (UseCase'ы и порты), Infrastructure (БД, ZIP, хранилище, очередь, токен), Presentation (чистые контроллеры), DI по слоям, `routes.php`, миграция, `LogChannelEnum::PRODUCTION`.
2. **Узкие контракты поставщиков** в `rebit.share/lib/Contracts/`: Commerce — оплаченные печатные строки группы (paidAt заказа, признак staff-группы) и число заказов группы, ждущих подтверждения оплаты (`mf_order.PAYMENT_STATUS='pending'` — открытая попытка G1); Organization — группы, у которых печать закрылась в интервале. Реализация и DI — у модулей-поставщиков. Media не меняется: `OriginalFilesInterface` уже даёт путь, тип и размер; код кадра в снимке заказа содержит код ребёнка.
3. **Сборка**: cron-команда `app:production:run` (раз в минуту, `#[WithLock]`) по курсору (`closesAt`, ID группы) создаёт версию 1 для групп, у которых печать закрылась после старта (L1-DEC-08) и прошёл запас (L1-DEC-01), затем сама собирает ожидающие версии под арендой (повтор до 3 раз, зависшая аренда подхватывается) и удаляет просроченные файлы (L1-DEC-04); уникальность group + deadline + version и group + deadline + строка заказа.
4. **Состав**: только `physical`-строки оплаченных заказов с `paidAt < closesAt`; prints = quantity × printCount; digital/bundle/pending/unpaid/late исключены; пустой состав — состояние «нет оплаченной печати» без ZIP. Версия неизменяема: строки снимка хранятся в БД.
5. **Дополнения** (L1-DEC-02): оплаты, подтверждённые после снимка с `paidAt` до срока, видны в блоке; организатор собирает дополнение — новую версию только с новыми строками.
6. **API** (чистые контроллеры, один RequestDto на action):
   - PRD-01 `GET /api/v1/production/groups` — состояние печати групп своей области (для колонки «Печать»);
   - PRD-02 `GET /api/v1/groups/{groupId}/production` — состав, исключённое, версии, `archive{state, url?, expiresAt?, version}`; url — только у готовой;
   - PRD-03 `POST /api/v1/groups/{groupId}/production/versions` — организатор: первая сборка для старой группы или дополнение; Idempotency-Key;
   - PRD-04 `GET /api/v1/production/versions/{versionId}` — версия и её архив;
   - PRD-07 `GET /api/v1/production/versions/{versionId}/export` — CSV UTF-8 с BOM, `;`, экранирование формул;
   - PRD-10 `GET /api/v1/public/production/archives/{token}` — ZIP без входа; срок/отзыв проверяются до выдачи; `Cache-Control: private, no-store`; токен не в логах (nginx-map + stage `backend.conf`);
   - `POST /api/v1/production/versions/{versionId}/renewal` — только организатор: перевыпуск ссылки (L1-DEC-03; старая перестаёт работать), для удалённого по сроку файла — сборка заново (L1-DEC-04);
   - PRD-01 дополнительно принимает `groupIds` — состояние печати строк текущей страницы «Ссылок и сроков» одним запросом.
   - «Скачать архив» в кабинете открывает ту же ссылку версии, что копируется для лаборатории: браузерная загрузка не несёт Bearer.
7. **Ссылка**: токен = HMAC (ключ HKDF из `REBIT_ENCRYPTION_KEY`) от версии и поколения ссылки; в БД — sha256 токена, срок, поколение. Повторное «Скопировать ссылку» отдаёт ту же ссылку; перевыпуск увеличивает поколение — старая перестаёт работать. Открытый токен не хранится и не логируется.
8. **Хранение**: `<MOREFOTO_PRIVATE_FILES_PATH>/production/<groupUuid>/<versionUuid>.zip` (chmod 0600, атомарная запись), отдача через `/_protected/files/`; удаление файла по сроку (L1-DEC-04), состав и CSV остаются, файл версии можно собрать заново.
9. **Frontend** (L1-DEC-06): в «Ссылках и сроках» — значок состояния печати в строке группы и пункт меню «Архив печати» → диалог-блок «Печать»: состояние (собирается / готов / ошибка / нет оплаченной печати / ждёт срока), версия и дата, состав (позиций, отпечатков, продукция), «Скачать архив», «Скопировать ссылку», срок ссылки; для организатора — «Собрать архив» / «Собрать дополнение», «Перевыпустить ссылку». Без нового пункта навигации.
10. **Проверки**: PHPUnit (домен, UseCase, архитектура границы контроллеров), PHPStan, cs-fixer; frontend `npm run check`, unit; live E2E (`zzzz…-production.spec.ts`) и MySQL-верификатор сборки; миграция и модуль в `api/tools/e2e/prepare.php`.
11. **Документы**: `docs/waves/l1/README.md` (runbook выкладки: миграция, DoInstall, cron/consumer-сервисы stage, nginx `backend.conf`), граф (L1 review → merged следующей волной), патч MoreFoto `docs/waves/l1/morefoto-contract.patch` (PRD-10, уточнения PRD-02/04).

## Технические решения (без отдельного согласования)

- **L1-T-01.** Свой модуль `morefoto.production`, свои таблицы `mf_production_version`, `mf_production_line`, `mf_production_link`; межмодульные данные — только через контракты `rebit.share/lib/Contracts/*`, без SQL к чужим таблицам.
- **L1-T-02.** Снимок строк пишется в одной транзакции с версией; сборка ZIP — вне транзакции, по сохранённым строкам; исходные байты, sha256 сверяется при копировании.
- **L1-T-03.** Имена внутри ZIP — UTF-8, безопасные (без `/`, `..`, управляющих символов); одинаковые названия продукции различаются по productId (суффикс); имя скачиваемого файла — ASCII `print-<groupPublicId>-v<N>.zip` (ограничение `ProtectedFileResponse`).
- **L1-T-04.** Лимиты J1 (500 файлов, 2 ГиБ) к печати не применяются; свой предел числа файлов и размера с понятной ошибкой сборки.
- **L1-T-05.** Без очереди RabbitMQ: архив нужен лаборатории через час после срока, минутная задержка cron не важна. Одна команда `app:production:run` с блокировкой планирует, собирает и чистит; контейнеру cron нужен private-media только для чтения (`docker-compose-production.yml`), на stage — отдельный цикл-сервис по образцу `morefoto_stage_files_dispatcher` (runbook в `docs/waves/l1/README.md`).
- **L1-T-07.** Имя файла в архиве — `{код кадра}_x{отпечатков}.{расширение}`: код кадра Media = код ребёнка + номер (`A001` — ребёнок `A`, кадр `001`), поэтому файл ребёнка и кадра однозначен и с общим кадром двух детей (у каждого свой код). Пример плана `A001_0012_x3.jpg` уточнён до `A001_x3.jpg`.
- **L1-T-08.** Общая атомарная запись ZIP (tmp + chmod 0600 + rename, владелец корня хранилища) выносится в `rebit.share` и используется J1 и L1 — без копии кода.
- **L1-T-09.** PRD-07 отдаёт CSV из кабинета через общий ответ `csv()` базового контроллера с Bearer; тот же CSV лежит в корне ZIP.
- **L1-T-06.** Открытые попытки оплаты на момент сборки не блокируют её: версия запоминает число ожидающих заказов, они станут дополнением, если подтвердятся с `paidAt` до срока.

## Критерии приёмки

- После `closesAt` + запас архив собирается сам, без email и без действий сотрудника; повторный запуск и параллельные dispatch не создают вторую версию 1.
- В архиве ровно оплаченная печать до срока: prints = quantity × printCount; digital, комплекты, неоплаченные, ожидающие и поздние оплаты исключены; пустой состав — состояние без ZIP.
- Папки и имена соответствуют L1-DEC-05; байты файлов совпадают с оригиналами; CSV безопасен для Excel.
- Организатор и куратор своего учреждения видят блок; чужая область — 404; куратор не собирает и не перевыпускает.
- Ссылка без входа открывает только свою версию; неверный, истёкший, отозванный токен и соседняя версия — отказ; токен не в логах.
- Оплата, подтверждённая после сборки с `paidAt` до срока, видна и уходит в дополнение; уже собранные версии не меняются.
