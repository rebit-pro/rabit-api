# Issues #83 и #97 — хвосты G1: опрос оплаты после ухода со страницы и E2E реестра по позиции

## Цель и контекст

Оба замечания относятся к G1 (оплата ЮKassa, PR #80, слит `fc0cdb9`). Их взяли в работу 2026-09-25 вместе с #88 и #90; у каждой группы отдельная ветка и PR. Это issue-ветка, не волна: `docs/waves/graph.json` не меняется.

- [#83](https://github.com/rebit-pro/rabit-api/issues/83): `usePaymentReturn` очищает при размонтировании только уже поставленный таймер. Ответ запроса, который пришёл после ухода со страницы или смены попытки, снова ставит `setTimeout(poll)`: неактивный экран до 5 минут опрашивает статус и может вызывать лишние обращения к ЮKassa.
- [#97](https://github.com/rebit-pro/rabit-api/issues/97): G1-T09/G1-T10 берёт успешную карточную попытку из `listed[0]` и ожидает порядок `[bank_card, sbp]`. В прогоне ревью PR #89 реестр вернул `[sbp, bank_card]` при соблюдённой сортировке `CREATED_AT DESC, ID DESC` — тест упал на позиции.

- Ветка: `codex/issues-83-97-payment-followups`, worktree `/home/user/rabit-api-worktrees/issues-83-97-payment-followups`.
- Base: `origin/main` `94502a1`.

## Установленные факты

- «Вернуться к заказу» на странице возврата делает полную загрузку документа: JS-контекст уничтожается, и дефект #83 так не проявляется (проверено маркером в `window`). Дефект возникает при переходах внутри приложения: смена `attemptId` (тот же компонент) или переход по истории браузера.
- `createdAt` попытки берётся из часов при старте (`StartPaymentAttemptUseCase`), сортировка реестра — `CREATED_AT DESC, ID DESC`. Почему в прогоне ревью `createdAt` отказанной СБП оказался позже карточной, не установлено; это не доказанный дефект сортировки (issue явно просит не считать его таковым).

## Решения

- **R1 (#83).** Поколение опроса: `start()`, `recheck()` и размонтирование увеличивают счётчик и снимают таймер; ответ и ошибка чужого поколения ничего не меняют и таймер не ставят.
- **R2 (#97).** G1-T14 запоминает ID обеих попыток из URL возврата; G1-T09 находит попытки по ID, а порядок реестра проверяет как контракт: `createdAt` не возрастает.
- **R3.** Live-проверка #83 не зависит от тестового магазина: статусы отвечает тест через `page.route`, переходы внутри приложения — через History API и слушатель роутера; тест проверяет, что документ не перезагружался.
