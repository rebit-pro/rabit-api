# Доработка интерфейса: таблицы, рабочая область, корзина, меню «Съёмки», футер, база знаний

## Цель

Шесть замечаний пользователя от 13.10.2026 к кабинету и покупке:

1. Учреждения, съёмки и группы внутри съёмки — таблицы, как заказы и сотрудники (#92).
2. Табличные части отделить от фона страницы лёгким пастельным цветом рабочей области.
3. Корзина и заказ: компактно, меньше действий родителя при покупке.
4. Съёмки — отдельным пунктом меню.
5. Доработать футер.
6. Ссылка на базу знаний на странице входа (#129).

Первый результат — скриншоты нового вида desktop/mobile и коммит прототипа на ветке. Реализацию дальше ведём после того, как пользователь посмотрит скриншоты.

## Факты инвентаризации

- `UiDataTable` — общий компонент таблиц (сортировка, выбор, пагинация, карточки на mobile). Уже используют заказы, платежи, сотрудники, списки сотрудников, ссылки, каталог, виджеты страницы учреждения.
- API структуры (`/api/v1/institutions`, `/api/v1/shoots/{id}`) отдаёт страницы по 25 без параметра сортировки. Общего списка съёмок по всем учреждениям нет.
- Корзина и оформление читают одно состояние витрины (`liveState`/`liveQuote`); оформление — отдельная страница `/g/:token/checkout` с тремя галочками: «Состав и условия проверены», согласие на обработку ПДн, оферта.
- Выбор продукции — выпадающий список, количество и «Добавить в корзину» в диалоге кадра; на mobile блок заказа уходит под первый экран.
- Футер — `LegalFooter` в `BlankLayout`: строка продавца, три ссылки, «Разработано в ReBit Studio»; в галерее над ним ещё строка бренда.

## Решения (предложения для согласования по скриншотам)

- **UI-DEC-01. Рабочая область.** Таблица лежит на «подносе» пастельного морского оттенка (семантические токены `workspace` = `sea-100`, `workspace-border` = `sea-200`, `workspace-row-hover` = `sea-50` в `src/theme/tokens.ts`), строки таблицы — на белом. Применяется в `UiDataTable`, то есть ко всем таблицам кабинета одинаково.
- **UI-DEC-02. Учреждения и группы съёмки — `UiDataTable`.** Учреждения: название с адресом, съёмок, групп, приём открыт, куратор, действия. Группы съёмки: группа, тип, приём, печать до, электронные до, ответственный. Сортировка в пределах страницы до появления серверной (ниже).
- **UI-DEC-03. Меню «Съёмки».** Пункт между «Учреждения» и «Ссылки и сроки»: все съёмки доступных учреждений таблицей (съёмка, учреждение, дата, групп, приём открыт). Нужен новый `GET /api/v1/shoots` — в прототипе экран и контракт, backend после согласования.
- **UI-DEC-04. Корзина и оформление — одна страница.** Строки корзины компактными строками, справа итог, email, согласия и «Оформить заказ». Старый адрес `/g/:token/checkout` ведёт на эту же страницу.
- **UI-DEC-05. Без галочки «Состав и условия проверены».** Состав виден на той же странице; остаются согласие на ПДн (отдельное по 152-ФЗ) и принятие оферты. Нужна отметка пользователя: юридически значимое изменение формы.
- **UI-DEC-06. Выбор продукции списком.** Вместо выпадающего списка — список продукции с ценами; одно нажатие выбирает продукт, кнопка «В корзину · сумма». На mobile нижняя панель корзины в галерее: количество, сумма, «Оформить».
- **UI-DEC-07. Футер.** Две строки: бренд и навигация покупателя (как заказать, документы, оферта, политика), затем реквизиты продавца и «Разработано в ReBit Studio». Ссылка «Как заказать» ведёт в базу знаний родителя.
- **UI-DEC-08. База знаний.** На странице входа — кнопка «База знаний» в шапке (на телефоне — иконка) и карточка в правой колонке; в кабинете — пункт «База знаний» внизу бокового меню, открывается в новой вкладке (#129).
- **UI-DEC-09. Попутно #157.** Ссылки на документы в согласиях — цвет ссылок продукта, не синий браузера (`ConsentField`, общий с приглашением).

## Scope

Прототип (этот шаг): frontend всех пунктов, стенд скриншотов (Vite + подмена API в контейнере), скриншоты desktop 1440 и mobile 390 «до» и «после», коммит.

После согласования: `GET /api/v1/shoots` (UseCase, SQL, DI, контракт), серверная сортировка учреждений и групп, правки live E2E (адрес оформления, галочки, таблицы), полный `make test-e2e`, обновление базы знаний (#188).

## Исключено

- Страница заказа после оформления и оплата (кроме общих стилей); автозапуск оплаты сразу после оформления — отдельное предложение.
- Демо-экраны кабинета (`OrganizationListScreen` и другие) не переделываются.

## Риски

- Изменение `UiDataTable` меняет вид всех таблиц сразу — проверить заказы, платежи, ссылки, каталог и виджеты в панелях.
- Объединение корзины и оформления ломает live E2E, завязанные на `/checkout`; правка спеков — после согласования.
- UI-DEC-05 требует решения пользователя; до него backend по-прежнему получает `reviewed: true`.

## Критерии приёмки

- Учреждения, съёмки и группы съёмки — таблицы того же вида, что заказы; на mobile — карточки `UiDataTable`.
- Таблицы визуально отделены от фона страницы; без горизонтальной прокрутки на 390 px.
- Покупка: кадр → продукт одним нажатием → корзина-оформление на одной странице → заказ. Шагов меньше, чем сейчас.
- В меню есть «Съёмки»; на входе и в кабинете есть ссылка на базу знаний.
