# E4 — приватная витрина и серверный расчёт корзины

## Цель и границы

Покупатель по разрешённой capability видит защищённые превью, действующий каталог и получает серверный quote. MED-01, COM-08, COM-09; владельцы morefoto.media и morefoto.commerce. Источники: docs/waves/graph.json, ../MoreFoto/docs/04-bitrix-modules/backend-waves.json, ../MoreFoto/docs/05-rest-api/endpoints.json.

Вне scope: заказ/оплата E5/G2, публичная подготовка и передача ссылки F2, перенос снимков D3, production-продажи N2, долг #24/#26–28. Реальные данные тестового стенда допустимы; публичный обход lifecycle ради готовности запрещён. Развёртывание E4 добавлено отдельным поручением пользователя после ревью.

## Зависимости и решения

D2, E3, F1 присутствуют в main после merge PR #25. Одна ветка codex/e4-private-storefront от актуального main, один будущий PR.
D02–D05: принятые правила E3 (docs/waves/e3/README.md); D07/D10: docs/waves/w05/decisions.md. Цены без seed, копейки RUB, 50% только серверно подтверждённым сотрудникам на отмеченные товары; округление половины вверх. Порог физической продукции после скидки отдельно каждому ребёнку; подарок один active bundle. Closed сохраняет просмотр, запрещает новую покупку; preparing не выдаёт фото.

Принятое решение E4-DEC-01 (2026-09-21, пользователь: «Да, согласен»): строка COM-09 содержит assignmentId/productId/quantity. assignmentId — публичный ID конкретной связи ребёнок—снимок, выдаваемый MED-01. Сервер проверяет существование связи, capability, группу, ребёнка и готовность снимка; выводит childCode, фото, право сотрудника и суммы сам. Для bundle assignmentId выбирает ребёнка; состав нормализуется сервером по всему его разрешённому набору. Один снимок у разных детей имеет разные assignmentId; нельзя подменять связь первым ребёнком или доверять присланному childId. Будущий COM-10 принимает тот же состав, что COM-09; его реализация остаётся E5.

Согласованное уточнение сначала внести в канонический build.py MoreFoto и сгенерированные API/Postman, добавить переменную assignment_id; MED-01 описывает выдачу assignmentId. Сохранить точный patch внешних генераторов в ветке E4, поскольку соседний MoreFoto не имеет Git. Обновить deliveryState по подтверждённым merge receipts, принятые D02–D05 по отчёту E3; E4 inProgress, остальные незамерженные волны не активировать.

Технический анализ: существующий Domain/Conditions/Service/SalesPolicy уже считает суммы/подарки, переиспользовать. Live галерея/корзина ещё требуют подключения вместо demo-расчёта. Новые DTO пассивные, преобразования отдельными mapper. Контроллеры только типизированные DTO/UseCase/mapper и общий API base. Новые/изменённые UseCase и Service имеют содержательный русский class phpDoc.

## Приёмка и тест-кейсы

3. E4-MEDIA: тестовые фото готовые/неготовые и чужой группы; получить gallery и preview. Только допустимые защищённые версии, оригиналы/чужие данные не выдаются. Команда make test-e2e.
4. E4-QUOTE: реальный каталог/условия/подтверждение F1; POST COM-09 на границах порога, с изменением количества, bundle и M:N. Копейки/скидка/подарок совпадают с SalesPolicy; суммы/льгота от клиента отклоняются. Команды backend unit и make test-e2e.
5. E4-STALE: quote создан; сменить условия/назначение/состав либо дождаться TTL через управляемые часы. Проверка quote отклоняет устаревший fingerprint/истёкший токен. Команды backend unit и HTTP integration.
6. E4-ARCH: DTO без поведения, чистые controller, правильный DI и русские phpDoc. Команды PHPUnit architecture, PHPStan, php-cs-fixer по изменённым PHP.
7. E4-UI: обычное открытие тестовой ссылки, выбор фото/товара/количества и серверный пересчёт на desktop/mobile; ошибки не подменяются demo. Команда make test-e2e плюс ручной просмотр screenshots.
8. E4-GRAPH: актуальная карта; штатная проверка DAG/99 API ID/готовности (точную команду определить из tools/Makefile).
9. E4-PUBLISH: git diff --check, локальный gate PASS, один PR в main с зависимостями/ограничениями/условиями подключения.


## Технические находки для следующего этапа

D2 хранит связь в mf_photo_assignment по паре PHOTO_ID/CHILD_ID без публичного UUID. Для assignmentId нужна миграция/backfill существующих связей и генерация идентификатора при новых назначениях; существующие связи должны сохранять ID при повторной идемпотентной разметке. Проверять две связи одного снимка отдельно в E4-QUOTE.

GdPreviewRenderer сейчас пишет thumb/preview в публичный каталог upload/morefoto/previews. Одной выдачи защищённых URL MED-01 недостаточно: прямой URL файла должен быть закрыт либо файлы перемещены за защищённую выдачу с сохранением доступа административного UI. Это часть E4-MEDIA, учесть в DI/nginx/E2E и не считать существующие URL готовым приватным контрактом.

Capability lifecycle опирается на поля группы sentAt/closesAt и внутреннюю выдачу/отзыв; публичная активация только F2. Предметный доступ к группе предоставляется через контракт Organization. Commerce использует контракт Media для разрешённых assignment, а право сотрудника — через контракт Handoff, без SQL к чужим таблицам в UseCase.


## Компоненты защищённых изображений

PhotoImage сохраняет контракт src/alt и load/error, но для административного /api/v1/photos/... получает Blob через существующий HTTP-клиент с Bearer. GalleryImage сохраняет состояния загрузки/ошибки/повтора; публичный preview URL содержит capability и проверяется сервером при каждом запросе. Отмена загрузки и revokeObjectURL при смене src/unmount обязательны. Nginx запрещает прямой /upload/morefoto/previews, а renderer продолжает писать производные в тот же каталог; оригиналы не выдаются.


## Quote: решение реализации

Quote хранится по непредсказуемому 32-byte токену (в БД только SHA-256), с fingerprint нормализованных строк, полного разрешённого набора назначений/версий фото, ключа/сроков группы, каталога/условий и подтверждения льготы. Рабочий TTL — 15 минут, проверка срока по серверным часам; E5 обязан использовать ValidateQuoteUseCase и повторную проверку актуальности. Один bundle на ребёнка, цифровая позиция quantity=1, физическая quantity 1..99, максимум 100 строк. Неизвестные/повторные строки отклоняются. Для staff-галереи выбранные дети требуют подтверждения через порт Handoff; регулярная галерея не выдаёт льготу по клиентскому флагу. Публичная выдача quote не создаёт заказ. Каналы receiptChannels пусты до реального подключения фискальных каналов G2, наличие email-доставки H1 само по себе не является фискализацией.
