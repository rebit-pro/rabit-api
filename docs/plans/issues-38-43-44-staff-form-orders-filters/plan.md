# Issues #38, #43 и #44 — форма сотрудника и фильтры служебных заказов

## Цель и контекст

Исправить три дефекта live-кабинета, найденные при ручном тестировании и статическом ревью:

- [#43](https://github.com/rebit-pro/rabit-api/issues/43) (высокий приоритет). Форма «Новый/Редактирование сотрудника» не показывает ввод: имя и email стираются после ухода фокуса, роль визуально не меняется, блок замены не появляется. При этом «Сохранить» отправляет скрытое состояние.
- [#44](https://github.com/rebit-pro/rabit-api/issues/44). Панель фильтров «Заказы» выглядит криво: кнопки переносятся, раскладка «прыгает» по ширине, текст обрезается. Нужна компактная и ровная панель.
- [#38](https://github.com/rebit-pro/rabit-api/issues/38). После очистки крестиком поиска заказов модель получает `null`, и `apply()` падает на `.trim()`.

## Scope

### #43 — форма сотрудника

- `frontend/src/modules/morefoto/staff/useStaffEditor.ts`: черновик переводится на глубокий `ref` вместо `shallowRef`, как в остальных редакторах (`useStructureEditor`, `useManagementEditor`, `useProductEditor`, `useConditionsEditor`).
- `StaffFields.vue`, поле email: `autocomplete="off"` заменяется нераспознаваемым токеном. Chromium игнорирует `off` для полей, распознанных как email, и подставляет адреса самого организатора.
- `frontend/e2e/live/staff.spec.ts`:
  - проверка видимого состояния в сценарии создания;
  - новый UI-сценарий замены занятой группы при редактировании со сверкой PATCH.

### #44 — панель фильтров заказов

- `frontend/src/modules/morefoto/curator/components/StaffOrdersLiveScreen.vue` переходит на две зоны:
  - первая строка — поиск с лупой и кнопки «Найти»/«Сбросить» с `density="compact"`;
  - вторая — сетка уточнений: от 1280px 4 колонки, от 601 до 1279px 2×2, до 600px селекты во всю ширину и даты рядом.
- «Сбросить» неактивна, пока фильтры пусты.

### #38 — очистка поиска

- Нормализация на границе компонента: `@click:clear="filters.q = ''"`. Vuetify 3.10.11 вызывает `onClick:clear` после `reset()`, который ставит `null`. Тип `string` остаётся правдой для `apply()` и `staffOrderParams`.
- Live E2E заказов: очистка крестиком → «Найти» → `q` удалён из URL, ошибок нет.

### Исключено

- Фильтры учреждение/съёмка/группа (#39) — только учтено место в сетке.
- UX-правки формы сотрудника вне #43: маркеры обязательных полей, ошибки у полей, тексты режима редактирования в режиме создания.
- Demo-экраны `ManagementScreen`/`CuratorScreen` и backend.
- Граф волн и канонический план MoreFoto.

## Решения, риски и ограничения

- D1. Глубокий `ref` вместо иммутабельного `patch()`. Причина: минимальная правка, совпадает с соседними редакторами. `replacements` начинает пересчитываться сам. Риск: `staffApi.save()` получает reactive proxy. Это безопасно, тело запроса собирается из примитивов и массивов, которые сериализует axios.
- D2. Email: `autocomplete="staff-invite-email"`. Chromium подавляет автоподсказки для нераспознанного токена по умолчанию. Риски: гарантии для Яндекс Браузера нет; Firefox для такого токена может показать свою историю формы. Результат — ручная проверка пользователем (T06). Если станет хуже, вернуть `off`.
- D3. #38 закрывается на границе компонента (прецедент `StructureFields.vue` `@click:clear`), а не расширением типов до `string | null`.
- D4. Сетка фильтров использует явные раскладки вместо `auto-fit`, чтобы не было строк вида 3+1. Кнопки через `density="compact"` берут высоту из токенов UI kit (`--mf-control-compact`: 40px desktop, 44px touch).
- Ограничение: полный `make test-e2e` запускается после review без блокирующих замечаний. До review — быстрые проверки и адресный браузерный прогон на стабах API; он не заменяет live E2E.

## Критерии приёмки

1. Создание сотрудника: имя и email видны после ухода фокуса, смена роли переключает область доступа, чип выбранной группы виден, созданная запись совпадает с экраном.
2. Редактирование: значения на экране совпадают с телом PATCH, скрытых изменений нет.
3. Замена: для занятой группы видны предупреждение, чекбокс и причина. Без подтверждения — клиентская ошибка, с подтверждением — 200, прежний ответственный снят.
4. Фильтры заказов на 1920/1440/1280/1024/768/390:
   - кнопки в одной строке с поиском и одной высоты с ним;
   - значения по умолчанию и самые длинные статусы не обрезаются;
   - горизонтальной прокрутки нет.
5. Поведение фильтров не изменилось: Enter и «Найти» применяют фильтры, «Сбросить» очищает и неактивна без фильтров, URL-query прежний.
6. Очистка поиска крестиком → «Найти»: ошибок JavaScript нет, `q` удалён из URL и запроса.
7. `npm run check` и `npm run test:commerce` зелёные, live E2E зелёный после review.
