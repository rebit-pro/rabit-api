# Документация RaBit API

В RaBit API сохранены общая основа Share/Auth, приём заявок с сайта в `rebit.notification` и самостоятельная действующая лидогенерация `rebit.leadhunter`. Оба модуля заявок не относятся к удалённой P2P-части; торговая ветка Notification не включена.

Актуальное состояние приложения описывают [модули](modules.md), [HTTP API](api.md), [данные](database.md), [сценарии](scenario.md) и [архитектура](architecture.md). Результаты проверки и существующие дефекты — в [аудите](audit-rabit-api.md).

[Деплой 11 сентября 2026](deployments/2026-09-11-rabit-api.md): текущий production, проверки заявок сайта и LeadHunter, резервные копии и порядок отката.

Канонический продуктовый план находится в отдельном MoreFoto (следующие ссылки работают при соседнем локальном checkout): [карта модулей](../../MoreFoto/docs/04-bitrix-modules/README.md) и [REST API](../../MoreFoto/docs/05-rest-api/README.md). Эти документы описывают будущие возможности, а не готовый backend.

Старые материалы в `architecture-guide/`, `code-writing-rules/`, `how-to/` и `review/`, если они есть в локальном checkout, являются историческими справочными материалами. Они не задают текущий состав RaBit API; торговые примеры и примеры `fetchCollection()` для нового чтения не применяются. Приоритет имеют текущие инструкции проекта и `architecture.md`.

[Порядок реализации MoreFoto — 35 волн](../../MoreFoto/docs/04-bitrix-modules/backend-waves.md): самостоятельные предметы ревью, последовательные зависимости, REST-ID и критерии подключения. [Общий API-инвентарь](../../MoreFoto/docs/05-rest-api/README.md) сохраняет исходные 97 контрактов и дополнен платформенными SHR-01/NTF-01.

В этом репозитории доступны [пакет W00](waves/w00/README.md), [снимок плана](waves/w00/snapshot/backend-waves.md) и [снимок контрактов](waves/w00/snapshot/endpoints.json). Они позволяют проверить PR без локального MoreFoto. Snapshot сохраняет исходные тексты, ссылки и статусы каноники на дату переноса; ссылки из самого snapshot могут вести в соседний проект. Текущее состояние приёмки фиксируется в [реестре волн](waves/README.md), а не изменением замороженного снимка. Для новых волн действует уточнённое [разделение контрактов](architecture.md#контракты-и-di): технические — `Application/Contract`, предметные — корневая `Contracts`. Историческое правило об одном каталоге в W00 не переносится в новую реализацию.
