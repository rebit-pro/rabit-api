Runtime использует стек **`site`** и прежние пути **`/srv/rebit-p2p/`**. Переименование исходников в RaBit API не переносит существующие данные:

- файлы: `/srv/rebit-p2p/upload`;
- журналы: `/srv/rebit-p2p/logs`;
- том MySQL: `site_api-mysql`;
- том RabbitMQ: `site_rabbitmq-data`.

У FPM сохранён Docker config `rebit_backend_env_248`, у cron — отдельный `rebit_backend_env_leadhunter_20260904`. Проверено сохранение Env, Configs, Secrets, Mounts и команд запуска всех четырёх изменённых сервисов. Значения секретов в отчёте отсутствуют. У отключённого audit-consumer Docker изменил лишь порядок тех же mount-записей.

Миграции, удаление таблиц и деинсталляция записей старых модулей из БД не выполнялись. MySQL, RabbitMQ и остальные сервисы стека сохранили прежние ServiceSpec. Старые торговые consumers остаются с нулём реплик. `site_frontend` на `app.rebit-pro.ru` остаётся прежним отдельным runtime-сервисом; этот выпуск не выполняет его вывод из эксплуатации. Сайт `rebit-pro.ru` обслуживает отдельный `rebitpro_web`; его статический релиз и MoreFoto frontend не обновлялись.

**Не запускать для этого production без отдельной подготовки обычный `make deploy` или `docker stack deploy --prune` из переименованного проекта.** Имена стека/томов/путей отличаются от новых compose-значений. Перенос на `rabit-api` требует отдельной операции с данными и проверкой сервисов.
