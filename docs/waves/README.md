# Работа по волнам

Одна волна — одна ветка `codex/wNN-...` и один GitHub pull request. Код, контракт, проверка и описание ответственности ревьюируются вместе. Прямые feature-коммиты в `main`, объединение независимых волн и автоматический merge не используются.

| Волна | Ответственность | Статус |
| --- | --- | --- |
| [W00](w00/README.md) | Зафиксировать состав RaBit API и воспроизводимый снимок контрактов | Принята: [PR #1](https://github.com/rebit-pro/rabit-api/pull/1) |
| [W01](w01/README.md) | Удалить секреты из HTTP-логов | Реализована и проверена; [PR #2](https://github.com/rebit-pro/rabit-api/pull/2) |
| [W02](w02/README.md) | Срок и отзыв сессий; pending отдельно от блокировки | Реализована и проверена; [PR #4](https://github.com/rebit-pro/rabit-api/pull/4) |
| [W03](w03/README.md) | Multipart и постоянный владелец файла | Реализована и проверена поверх W02; [PR #5](https://github.com/rebit-pro/rabit-api/pull/5) |
| [W04](w04/README.md) | Окружение и регистрация модулей | Реализована и проверена поверх W03; ожидает ревью PR |
| W05–W34 | Предметные решения, продуктовые сценарии и подключение MoreFoto | Не начаты |

[Снимок полного плана](w00/snapshot/backend-waves.md) — 35 волн W00–W34. Каноника MoreFoto остаётся отдельной; при изменении состава новой волны обновляется её пакет ревью. Замороженный W00 служит исходной точкой и не переписывается под новые сценарии.

Новая история Git содержит пустой технический root-коммит, необходимый как base первого PR. Вся прикладная основа поступает через W00. После его принятия каждый следующий PR будет показывать только свою волну. Большой импорт существующей основы в W00 — однократная операция; он не означает реализацию новых бизнес-модулей.

PR волн образуют последовательность W01 → W02 → W03 → W04. База каждой следующей ветки — предыдущая волна; это сохраняет отдельный diff для ревью. После принятия родительского PR проверить базу следующего и перенаправить её на `main`. Слияние и production deployment выполняются после приёмки, отдельно от подготовки PR.
