Статус: backend реализован и проверен; браузерная приёмка не пройдена. Ветка `codex/c3-shoots-groups-calendar` начата от актуального `main` `895fee9873cd62316579d18512c8b2e3315c3d62` (13 сентября 2026).

## Границы

- Зависимость `C2` слита в main; D08/D10 приняты в `docs/waves/w05/acceptance.md` и `decisions.md`.
- ORG-06/07/08/09/10/12: самостоятельные съёмки учреждения, группы, свойства и назначения воспитателя. ORG-11 и финансовые/медийные сводки относятся к следующим волнам.
- Organization владеет съёмкой, группой и календарём; Access — назначением воспитателя и отзывом сессий; Auth — действующей учёткой и токеном.
- Запись выполняется с ревизией, scoped Idempotency-Key и историей одной локальной транзакции. Порядок блокировок: AccessState → Institution → Shoot → Group → StaffProfile → Auth.
- Обычный PATCH группы меняет название/назначение, не родителя, тип, состояние и сроки. Передача и продление — отдельные внутренние календарные команды; публичные Handoff/Support endpoints появятся в зависимых волнах.

## Уточнение контрактов

ORG-06 использует `page` и `pageSize` (1–100, по умолчанию 50), сортировку с устойчивым вторым ключом. ORG-08 доступен организатору и возвращает `groups: {items, meta}` с теми же параметрами пагинации групп; `assignmentSignature` относится к общему состоянию Access. Неограниченных вложенных списков нет.

Дата съёмки — nullable YYYY-MM-DD: отсутствие поля PATCH сохраняет дату, null очищает. Группы разных съёмок могут иметь одинаковые названия. `groupKind` задаётся при создании: regular или staff.

ORG-10/12 принимают `reason` (не более 2000 символов); при замене или снятии занятого назначения обязательны причина, `replaceAssignments: true` и актуальная подпись. Причина записывается в историю; оба затронутых сотрудника получают новую версию доступа и теряют старые сессии. Повтор команды не отзывает новые сессии.

Календарь использует серверные часы, Europe/Moscow и UTC в БД. Первая передача устанавливает sentAt, closesAt = +7 календарных дней, deliveryDueAt = closesAt +7 дней. На границе now >= closesAt группа закрыта. Повторная передача не сдвигает сроки. Продление требует нового срока позже прежнего и now, причины и актуальной ревизии.

## Проверенный backend

PHPUnit: 341 тест / 1089 assertions; native C3: 192 проверки; регрессии C2: 136 и E2: 95. PHPStan без ошибок, lint 401 модульного PHP-файла, style 65 изменённых PHP-файлов. Подробности — [verification.json](verification.json).

Native проверки выявили и закрыли три дефекта: преобразование Bitrix Date/DateTime на границе чтения, несовместимый ключ календарной идемпотентности и вложенный rollback CUser при отзыве сессии. `Auth::clearToken` теперь очищает только Auth-поля SQL-запросом в транзакции вызывающего, как уже существующий `revokeToken`. Реальный SQL trigger подтверждает полный откат группы, назначений, истории, receipt и обоих токенов при сбое внутри отзыва.
