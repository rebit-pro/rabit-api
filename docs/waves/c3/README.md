# C3 — съёмки, группы и календарь

Статус: готово к ревью; backend, frontend и обязательная локальная приёмка завершены. Ветка `codex/c3-shoots-groups-calendar` начата от `895fee9873cd62316579d18512c8b2e3315c3d62`, затем перебазирована на актуальный `main` `b01be326e607c5cfafaeff587f29048f6802a636` после разрешённого merge A8 #14 (13 сентября 2026).

## Границы

- Зависимость `C2` слита в main; D08/D10 приняты в `docs/waves/w05/acceptance.md` и `decisions.md`.
- ORG-06/07/08/09/10/12: самостоятельные съёмки учреждения, группы, свойства и назначения воспитателя. ORG-11 и финансовые/медийные сводки относятся к следующим волнам.
- Organization владеет съёмкой, группой и календарём; Access — назначением воспитателя и отзывом сессий; Auth — действующей учёткой и токеном.
- Запись выполняется с ревизией, scoped Idempotency-Key и историей одной локальной транзакции. Порядок блокировок: AccessState → Institution → Shoot → Group → StaffProfile → Auth.
- Обычный PATCH группы меняет название/назначение, не родителя, тип, состояние и сроки. Передача и продление — отдельные внутренние календарные команды; публичные Handoff/Support endpoints появятся в зависимых волнах.

## Уточнение контрактов

ORG-06 использует `page` и `pageSize` (1–100, по умолчанию 50), сортировку с устойчивым вторым ключом. ORG-08 доступен организатору и возвращает `groups: {items, meta}` с теми же параметрами пагинации групп; `assignmentSignature` относится к общему состоянию Access. Неограниченных вложенных списков нет.

Дата съёмки — nullable YYYY-MM-DD: отсутствие поля PATCH сохраняет дату, null очищает. Группы разных съёмок могут иметь одинаковые названия. `groupKind` задаётся при создании: regular или staff.

ORG-10/12 принимают `reason` (не более 2000 символов); при замене или снятии занятого назначения обязательны причина, `replaceAssignments: true` и актуальная подпись. Причина записывается в историю; оба затронутых сотрудника получают новую версию доступа и теряют старые сессии. Повтор команды не отзывает новые сессии.

Календарь использует серверные часы, Europe/Moscow и UTC в БД. Первая передача устанавливает sentAt, closesAt = +7 календарных дней, deliveryDueAt = closesAt +7 дней. На границе now >= closesAt группа закрыта. Повторная передача не сдвигает сроки. Продление требует нового срока позже прежнего и now, причины и актуальной ревизии.

## Приёмка

Обязательны PHP lint/style/PHPStan/PHPUnit, native Bitrix/MySQL проверки настоящих миграций, прав, конкурентной записи, откатов, идемпотентности, календаря; реальный браузерный E2E редактора и desktop/mobile визуальная проверка. Каждый результат записывается только после выполнения.

A8 #14 слита в main отдельным разрешённым действием. C3 перебазирована на этот main; проверки выполняются на принятой базе плюс только собственный diff C3.

Новые PR автоматически не сливаются; deployment не выполняется.

## Проверенный backend

PHPUnit: 341 тест / 1089 assertions; native C3: 198 проверок; регрессия C2: 138. Регрессия каталога E2: 95. PHPStan без ошибок, lint 401 модульного PHP-файла, style 68 изменённых PHP-файлов. Подробности — [verification.json](verification.json).

Native проверки выявили и закрыли три дефекта: преобразование Bitrix Date/DateTime на границе чтения, несовместимый ключ календарной идемпотентности и вложенный rollback CUser при отзыве сессии. `Auth::clearToken` теперь очищает только Auth-поля SQL-запросом в транзакции вызывающего, как уже существующий `revokeToken`. Реальный SQL trigger подтверждает полный откат группы, назначений, истории, receipt и обоих токенов при сбое внутри отзыва.

## Реальный редактор

В live-кабинете доступны `/cabinet/institutions` → `/:institutionId` → `/:institutionId/shoots/:shootId`. Организатор создаёт и изменяет учреждения, съёмки и группы; куратор/руководитель читают только назначенные учреждения и съёмки. Редактор групп остаётся доступен только организатору. Страницы читают реальный API с пагинацией 25 записей. ORG-04 и ORG-11 не вызываются; финансовые и медийные значения не подставляются из demo.

Назначение воспитателя поддерживается backend C3 и проверено native; выбор сотрудника в UI ожидает реальных assignment-options B2. Текущий UI показывает факт назначения, сохраняет его при переименовании и не подставляет вымышленные списки сотрудников. Даты закрытия/доставки показываются из серверной проекции; команды передачи/продления остаются внутренними до Handoff/Support.

Карта компонентов: тонкие route views выбирают live/demo; `StructureScreen` компонует загрузку, ошибки, список и диалог; `StructureList` показывает записи и сроки; `StructureFields` содержит поля; `useStructurePage` загружает страницы, `useStructureEditor` сохраняет черновик и повторяет мутации; `model.ts` определяет только фактическую проекцию C3, `api.ts` — HTTP.

Перед отправкой браузер сохраняет исходные method/path/body/key в черновик текущего пользователя. Неопределённый результат замораживает поля и повторяет тот же запрос после reload и повторного входа. 401/403 не стирают ключ ранее начатой операции. 409 сохраняет введённые поля; явная команда «Загрузить актуальные данные» заменяет их серверными значениями и ревизией. Demo-модель и её редакторы сохранены отдельно.

В `frontend/e2e/live/organization.spec.ts` проверяются создание и durable чтение, две независимые съёмки, nullable дата, пагинация, 409, потеря успешного ответа, отзыв сессии, server-side scope/403, запрет календарных полей и мобильная форма. Перехват потери ответа сначала выполняет настоящий POST через `route.fetch()` и лишь затем обрывает доставку; API и БД не подменяются.

## Найденные HTTP-дефекты

Bitrix добавляет matched route values в GET до binder. Фабрики C2/C3 теперь разбирают только клиентский query из исходного URI, иначе валидные маршруты с UUID ошибочно получали 422. Native HTTP воспроизводит настоящий GET dictionary/binder; C2 PATCH и scalar/array query spoof проверяются вместе с C3.

C3 переведена в `review`. Полный live E2E на новой БД: **25/25**, без повторов, пропусков и flaky; frontend check/build и **155 unit-тестов** прошли. Demo-регрессия затронутого R07: **21 сценарий / 48 шагов**; весь demo-набор повторно не запускался. Просмотрены **6 desktop/mobile снимков**, два диалога пересняты после анимации на том же стенде. См. `browser.json`, `demo.json`, `visual.json`. Merge и deployment этой волны не выполнялись.


## Повторный запуск

Из корня ветки C3:

```sh
bash api/tools/run-c3-structure-integration.sh
make e2e-up
make e2e-test E2E_STATE=/absolute/path/to/state.json
make e2e-down E2E_STATE=/absolute/path/to/state.json
```

`e2e-up` выводит State и локальный URL; `e2e-test` требует новую базу, поскольку первым проверяется пустой каталог. Порядок, образы и настройки kernel/vendor — в `docs/waves/a8/README.md`. Native HTTP проверка и браузерный E2E сохраняются отдельно. После завершения остаются только локальные отчёты, ресурсы стенда удаляются по owner-label.

Адресная demo-регрессия из `frontend/`:

```sh
npm exec --no -- start-server-and-test e2e:server http://127.0.0.1:4173 'cross-env TS_NODE_PROJECT=tsconfig.e2e.json cucumber-js --config cucumber.mjs --tags @r07 --format json:reports/e2e/c3-organization.json'
```

Для Docker нужен сетевой интерфейс: допускается изолированная внутренняя сеть, но `--network none` переводит Chromium в настоящий offline-режим и закономерно ломает онлайн-сценарии demo. Подменять browser network state для прохождения тестов не нужно.
