# Ограничения и отдельные находки

## Границы C3

- Назначения воспитателей работают в backend и покрыты native проверками, но их UI ожидает assignment-options B2. Текущий редактор создаёт группу без назначения и сохраняет имеющееся назначение при переименовании.
- Передача ссылки и продление календаря реализованы внутренним контрактом/UseCase и проверены native. Их публичный UI/HTTP относится к Handoff/Support. Редактор C3 показывает серверную проекцию календаря; финансовые и медийные сводки не подставляются.
- ORG-04 и ORG-11 не включены. Следующие волны запускаются только после merge C3.

## Прежние дефекты вне C3

- C2 не передаёт reason в замене куратора/руководителя, хотя D08 требует причину. C3 требует причину в собственном сценарии воспитателя; исправление ORG-03/05 остаётся отдельным изменением.
- В редакторе каталога A8 (`frontend/src/modules/morefoto/catalog/useProductEditor.ts`) ветка любого HTTP < 500 сбрасывает pending и requestId. После успешного POST с потерянным ответом и последующего 401/403 это может потерять исходный ключ и допустить дубликат при новом сохранении. В C3 аналогичный путь исправлен и проверяется отдельным E2E; файл каталога в эту волну не включён. Находка подтверждена чтением кода, полный составной browser-сценарий A8 отдельно не запускался.
- Vite сообщает о прежнем отсутствующем `auth-pattern-dark.svg`; MoreFoto live-экраны используют светлую тему. PHPUnit выводит два прежних предупреждения о кешировании не-readonly DtoClassMetadata/DtoParameterMetadata без clone.

## Окружение и неуспешные попытки

- На машине повторялся сбой временных AF_UNIX сокетов Docker Desktop. Восстановление выполнено с разрешения пользователя и резервированием каталогов; данные контейнеров/томов не сбрасывались.
- PHPStan выполняется одним процессом (`--debug`), чтобы не превышать ограничение памяти контейнера; анализ не пропускается.
- Первый live-прогон: 21/25. Исправлен реальный перехват фокуса общим диалогом после открытия списка типа группы; три остальные ошибки были в новых тестах (чтение даты из краткого mutation-ответа, неоднозначный мобильный селектор, вход другой ролью без выхода). Второй live-прогон: 24/25; единственный отказ был неверным ожиданием 403 вместо намеренного 404 для чужой области. Приложение в этой итерации не менялось; ожидаемый ответ сверён с ListShootsUseCase. Итоговый прогон на новой БД выполнен целиком: 25/25, без повторов и пропусков.
- Первый demo R07 был ошибочно запущен с Docker `--network none`: Chromium возвращал `navigator.onLine=false`, и все 21 сценарий остановились при входе. Диагностика подтвердила `false` без интерфейса и `true` во внутренней сети. Повторный прогон во внутренней сети прошёл: 21 сценарий / 48 шагов, без подмены navigator.onLine и без правок приложения.
