# E1 — внутреннее ядро каталога

Готовый самостоятельный модуль `morefoto.commerce`: создание товара, частичное изменение и список с пагинацией. Ветка начинается от `main` `2ac4ef9b3e4b63d734fc3dda5240cab50a550d44`; B1/W06 и C1 не нужны для установки, тестов или merge.

E1 вместе с B1 разблокирует E2 — защищённые HTTP COM-01/02/03. В этой волне HTTP, права сотрудников, продажи, комплекты и скидочные расчёты не подключены. D02 остаётся открытым: реальные товары и цены не утверждены и не создаются миграцией.

## Реализация

- Native install/include/DI Bitrix; namespace `Morefoto\Commerce` регистрирует Loader. Общие composer, bootstrap, роуты и конфигурация анализатора не меняются.
- `MfProduct` / `b_hlbd_mf_product`: публичный UUID v4, реквизиты товара и UTC-время. Глобальная строка `mf_catalog_state` содержит `revision`, начиная с 1. Удаления товара нет; `active=false` сохраняет запись.
- `CreateProductUseCase`: принимает `ProductInputDto`, создаёт запись и возвращает UUID + новую ревизию.
- `UpdateProductUseCase`: принимает UUID, текущую **глобальную** ревизию и хотя бы одно поле. Изменение другого товара тоже делает старую ревизию недействительной. `false`, `0` и пустая строка учитываются; `null` в внутреннем DTO означает отсутствие поля. Будущий HTTP-адаптер должен отклонять явно переданный JSON null.
- `ListProductsUseCase`: возвращает `items`, `revision`, `page`, `pageSize`, `total`; включает неактивные товары для служебного каталога. Стабильный порядок — внутренний ID ASC. Для продолжения чтения той же версии можно передать `revision`; при изменении каталога пагинация начинается заново.
- Репозиторий возвращает D7 DB Result; строки читает Application и преобразует в immutable DTO. Objectify и N+1 отсутствуют.

Изменение берёт exclusive lock единственной строки ревизии; список — shared lock на время count и чтения страницы. Товар и новая ревизия записываются в одной InnoDB-транзакции. Ошибка и устаревшая версия не изменяют данные. Сценарий владеет своей транзакцией READ COMMITTED; запуск внутри уже начатой транзакции отклоняется до SAVEPOINT/rollback, сохраняя работу вызывающего кода. Все изменения каталога должны проходить через эти сценарии: прямые SQL/HL-правки обходят глобальную ревизию.

## Технические границы

Все строки — UTF-8 без NUL. `name` — непустое название до 255 символов, `description` до 4000, `format` и `unit` до 100. Деньги хранятся целым числом копеек; `price` и `printCount` допускают 0..2147483647 по вместимости native integer UF. `kind`: physical/digital/bundle. Правила соответствия kind, печати, формата и цены намеренно не добавлены. Пагинация: page 1..1000000, pageSize 1..100. Это технические ограничения хранения и нагрузки, а не ассортиментная политика.

## Установка и откат

Требуются PHP 8.4, MySQL 8, установленный native highloadblock и Sprint Migration. Применить активную миграцию `Version20260911220001`, установить `morefoto.commerce` штатным установщиком модулей, затем включить его через `Loader::includeModule('morefoto.commerce')` из доверенного bootstrap будущего потребителя. Сервисы разрешаются через штатный ServiceLocator в bootstrap/DI. E1 не добавляет публичных точек входа.

Повторная миграция сохраняет товары и ревизию. `down()` удаляет только пустой каталог; при данных останавливается. Удаление модуля сохраняет таблицы. DDL MySQL не является транзакционным; миграция поддерживает повторное применение после прерывания.

## Проверки

- Полный PHPUnit на main + E1: **156 тестов, 660 assertions**, без PHPUnit notices. Два прежних сообщения логгера Share о DTO metadata остаются вне E1.
- Настоящие Bitrix **25.750.0**, MySQL **8.0.45**, PHP **8.4.23**: **51 проверка**. Native install/Loader/DI/HL, повторная миграция, integer/Unicode round-trip, PATCH, глобальный CAS, пагинация, constraints, атомарный откат, запрет nested transaction, реальные блокировки между двумя соединениями и сохранность данных при uninstall.
- PHPStan, PHP lint и принятый PHP CS Fixer; результаты в `verification.json` и `integration.json`.

Воспроизведение: `bash api/tools/run-e1-catalog-integration.sh`. Runner создаёт отдельные `rabit-e1-tests` и `rabit-e1-mysql`, отказывается использовать уже существующие, хранит БД в tmpfs, не открывает host-порты и удаляет только свои ресурсы. Ядро и vendor подключены read-only. Базовая W02 bootstrap-фикстура используется без копирования; highloadblock устанавливается настоящим InstallDB. Production-конфигурация, данные, внешние сервисы и HTTP не участвуют.
