# E5 — заказ, снимок покупки и личный ключ

Ветка `codex/e5-order-checkout` от main `8cba22c7655b5886d5fe663523214bcd059e674b`. Зависимость E4 слита PR #30. E5 реализует COM-10…13 в `morefoto.commerce`, решения E5-DEC-01…05 приняты пользователем 22.09.2026. План и журнал: `docs/plans/E5_order-checkout/`.

Покупатель оформляет заказ из проверенного серверного расчёта и открывает его по личному ключу. Организатор и куратор видят заказы своей области. Заказ хранит неизменяемый снимок состава, цен, подарка и скидок; оплата, файлы и печать остаются следующими волнами.

## Контракты и границы

- COM-10 `POST /api/v1/public/galleries/{gallery_token}/orders`. Обязателен `Idempotency-Key` (32 hex), область повтора — capability галереи. Порядок: флаг оформления (403 `PURCHASE_DISABLED`) → capability (404) → preparing (409 `GALLERY_NOT_READY`) → резерв ключа → другое тело (409 `IDEMPOTENCY_CONFLICT`) → повтор (201, тот же заказ и ключ, в том числе после закрытия) → закрытая группа (409 `GALLERY_CLOSED`) → покупатель (422 по полю) → проверка quote → создание. Ответ 201, `Location: /api/v1/public/orders/current`.
- Устаревший расчёт: `QUOTE_EXPIRED`, `QUOTE_STALE`, `PRICE_CHANGED` с новым `quote`, `quoteToken`, `expiresAt` в `error.details`. Один заказ на quote: второй ключ с тем же расчётом — 409 `QUOTE_ALREADY_USED`.
- COM-11 `GET /api/v1/public/orders/current` с `X-Order-Key`: покупательская проекция и `period` из календаря Organization. Отсутствующий, неверный, отозванный и истёкший ключ, номер MF и токен галереи дают одинаковый 404 `ORDER_NOT_FOUND`.
- COM-12 `GET /api/v1/orders`, COM-13 `GET /api/v1/orders/{order_id}`: право `order.read` (организатор — всё, куратор — свои учреждения); head/teacher — 403 `FORBIDDEN`; чужой заказ — 404. Область и фильтры в SQL до LIMIT, страница — три запроса без N+1. `late`/`settlement` — 422 `FILTER_UNAVAILABLE` до G1/I1–I3. Перед выдачей права сверяются повторно (409 `ACCESS_CHANGED`).
- COM-08: `capabilities.purchaseEnabled` отражает флаг `MOREFOTO_CHECKOUT_ENABLED` (по умолчанию выключен), `receiptChannels=[]` до G2, `purchaseTerms=null`.
- Смежные изменения: `rebit.share` — `createdJson()` у публичного контроллера и `error.details`; Access — `order.read`; Media — `ChildPhotosInterface` (готовые кадры детей группы без URL).

## Хранение и ключи

Миграция `20260922120001`: `mf_order`, `mf_order_line`, `mf_order_access_key`, `mf_order_checkout`. Ограничения БД: один заказ на quote, один действующий ключ на заказ (генерируемый `ACTIVE_ORDER_ID`), согласованные суммы, вид строки и кадр, завершённый чек повтора. `down()` не удаляет таблицы с заказами.

Личный ключ — 32 случайных байта в 64 hex, в БД только SHA-256, срок 30 календарных дней по Москве. Копия для повтора оформления зашифрована AES-256-GCM ключом HKDF-SHA256 из Idempotency-Key клиента; сам Idempotency-Key хранится хешем. Сырые ключи, Idempotency-Key и токен галереи в БД, логах и служебных ответах отсутствуют.

## Frontend

Live-сборка использует настоящий API для оформления (`/g/:token/checkout`), заказа по ключу (`/orders/access/:orderKey`) и служебных заказов (`/cabinet/orders`, навигация по `order.read`). Оплата остаётся недоступной (`demoOnly`). Потерянный ответ повторяется с тем же ключом и тем же телом; изменение цены обновляет расчёт и требует нового подтверждения. При восстановлении сохранённую попытку сбрасывает только ответ, который сервер даёт после поиска по ключу повтора; `PURCHASE_DISABLED`, 408/429 и другие отказы до поиска оставляют экран восстановления с прежними ключом и телом. Миниатюры в заказе по ключу не показываются (E5-DEC-03); организатор видит служебные превью, куратор — коды кадров. Nginx исключает `/orders/access/` из access log.

## Подключение и ограничения

- Оформление включается только флагом `MOREFOTO_CHECKOUT_ENABLED=1` на изолированном стенде; stage/production — отдельное решение при развёртывании. Реальные продажи требуют оплаты (G1), реквизитов, оферты и согласия на ПДн (D09/N2).
- Для подключения нужны согласованные backend (миграция, DI, маршруты), frontend и nginx.
- Вне E5: оплата и чеки (G1/G2), поздний платёж и исправления (I1–I3), файлы (J1–J3), восстановление ключа куратором (K1), превью для куратора (I1), полные ролевые карточки (N1).
- Канонический контракт MoreFoto уточнён по решениям E5; воспроизводимый diff внешних файлов — `morefoto-contract.patch` (соседний каталог не является Git checkout).
