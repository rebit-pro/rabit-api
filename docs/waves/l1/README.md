# L1 — архив оплаченной печати и ссылка для ручной передачи

Ветка `codex/l1-print-archive` от main `cc92006`. Зависимости D1, F2, E5, G1, E7 слиты; решения D06 (подтверждено 15.10.2026) и D10 приняты, L1-DEC-01…08 приняты пользователем 15.10.2026 («рекомендации L1 принимаю все»). План и журнал: `docs/plans/L1_print-archive/`.

После окончания приёма печати группы система сама собирает ZIP оригиналов и `состав.csv` только по оплаченной печати. Организатор и куратор учреждения видят это в «Ссылках и сроках» и передают архив лаборатории ссылкой без входа. Email лаборатории — L3, здесь его нет.

## Решения

| ID | Принято |
| --- | --- |
| L1-DEC-01 | Версия 1 собирается через 1 час после `closesAt` — сверка G1 успевает подтвердить оплаты последних минут |
| L1-DEC-02 | Оплата, подтверждённая после сборки с `paidAt` до срока, — в дополнение (новая версия только с новыми строками); оплата после срока (`latePayment`) в печать не идёт |
| L1-DEC-03 | Ссылка действует 14 дней от сборки; копирование отдаёт ту же ссылку; перевыпуск — только организатор, прежняя ссылка перестаёт открываться |
| L1-DEC-04 | ZIP хранится столько же, сколько ссылка, затем удаляется; состав и CSV остаются, архив можно собрать заново |
| L1-DEC-05 | Папка = продукция из оплаченного снимка; файл на ребёнка и кадр `<код кадра>_x<отпечатков>.<ext>` (код кадра Media уже содержит код ребёнка: `A001` — ребёнок `A`, кадр `001`); `состав.csv` в корне |
| L1-DEC-06 | Блок «Печать» в «Ссылках и сроках»: значок в строке и окно «Архив печати» из меню строки; нового пункта меню нет |
| L1-DEC-07 | Организатор — всё; куратор учреждения — смотреть, скачать, скопировать ссылку; остальные — 403 |
| L1-DEC-08 | Автоматически собираются только группы, печать которых закрылась после выкладки (момент миграции); старые — кнопкой организатора |

## Контракты

| Где | Что |
| --- | --- |
| `morefoto.production` | Новый модуль: `mf_production_version`, `mf_production_line`, `mf_production_schedule` (курсор планировщика и момент выкладки), `mf_production_request` (Idempotency-Key). Миграция `20261015120001` |

| PRD-03 `POST /api/v1/groups/{group_id}/production/versions` | Организатор: архив закрытой до выкладки группы или дополнение; Idempotency-Key |

| `POST /api/v1/production/versions/{version_id}/renewal` | Организатор: перевыпуск ссылки; для удалённого по сроку или неудавшегося архива — сборка заново |

| `Rebit\Share\Infrastructure\File\AtomicZipWriter` | Общая атомарная запись ZIP; J1 переведён на неё |

## Выкладка (stage)

Новый модуль — runtime-симлинк, адресная миграция и DoInstall, как у J1:

1. `api` релиза; симлинк `runtime/public/local/modules/morefoto.production`.
2. Preview: `SELECT COUNT(*) FROM b_hlbd_mf_group WHERE UF_SENT_AT IS NOT NULL AND UF_CLOSES_AT<=UTC_TIMESTAMP();` — эти группы автоматически не соберутся (L1-DEC-08).
3. `backup.sh` → `restore-check.sh` → `migrate.sh up 20261015120001` → `DoInstall` модуля.
4. `switch-backend.sh` + DI-smoke (`RunProductionUseCase`, `ProductionController`, `PublicArchiveController`).
5. Cron: команда `app:production:run --limit=20` раз в минуту. На stage — в цикле сервиса-диспетчера по образцу `morefoto_stage_files_dispatcher` или отдельным сервисом-циклом; контейнеру нужны `private-files` (запись) и `private-media` (чтение), `REBIT_ENCRYPTION_KEY` и `MOREFOTO_PRIVATE_FILES_PATH`.
6. `backend.conf` stage: строка `~^/api/v1/public/production/archives/ 0;` в map access-лога (alias `/_protected/files/` уже покрывает `production/`).
7. Frontend.

Откат — возврат кода; таблицы остаются. `down` миграции после выкладки не выполнять: он удаляет версии, а повторный `up` переставит момент выкладки (группы, закрытые между ними, перестанут собираться автоматически).

## Ограничения

- Очередь групп PRD-01 по `institutionId/shootId/page`, задания печати, старт, комплектация, перепечатка, возвраты — L2/I2/I3.
- Ёмкость диска под ZIP не замерена — пилот N3.
- Ссылка не привязана к лаборатории: кто её получил, тот скачает архив до срока или перевыпуска.
