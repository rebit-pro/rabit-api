# D2 — привязка фотографий к детям и обложка группы

Статус: готово к ревью, обязательная локальная приёмка завершена. Ветка `codex/d2-photo-labeling` от `main` `c32b98e7c7407592c54c9ee382e994d7fa611955`; зависимость D1 слита. Реализация находится в Rabbit P2P / `rabit-api`, каноническая продуктовая документация остаётся в совместном проекте MoreFoto/BorrowPhoto.

## Результат волны

Добавлены атомарные операции организатора:

- `POST /api/v1/groups/{group_id}/photo-assignments` — присвоение одной пачке готовых фотографий следующего кода ребёнка;
- `PUT /api/v1/groups/{group_id}/cover` — выбор обложки группы.

Обе операции требуют `Idempotency-Key`, проверяют текущую revision и доступ пользователя до replay. Повтор с тем же ключом и телом возвращает исходный результат, другое тело с тем же ключом отклоняется. Смешанная пачка с чужой, повторной или неготовой фотографией не оставляет частичных изменений.

Схема хранит стабильный UUID ребёнка, канонический код вида `A001`, порядок кадра внутри ребёнка, M:N-связь фотографии с детьми, обложку группы и журнал идемпотентности. Одна фотография может быть одновременно размечена, например, `A001 · B001`; прежнее одиночное поле сохранено как совместимый первый элемент для следующих волн.

`GET /api/v1/shoots/{shoot_id}/photos` возвращает assignment-массив, sequence, агрегированную media revision и обложки. Фильтры `groupId`, `childCode` и `assigned` исполняются на сервере. Live frontend использует реальный API для разметки и обложки; перенос кадров D3 в live-режиме намеренно не включён.

## Проверка

Backend-проверки на disposable MySQL прошли: PHP lint, PHPStan, PHPUnit, миграции и Bitrix fixture. Frontend прошёл ESLint, Vue typecheck, E2E TypeScript, 158 unit-тестов и production build.

После финального исправления восстановления группы из deep-link повторно прошли frontend checks/build, целевой реальный сценарий D1/D2 и полный набор из 41 Chromium-сценария. Проверены M:N-разметка, фильтры, обложка, optimistic CAS, идемпотентность, запрет чужой группы, атомарный отказ смешанной пачки, роли, приватная выдача и ошибки файлов. Retry, skip и flaky отсутствуют; временный стенд `rabit-e2e-adc3ba213515` удалён.

Desktop 1440 px и mobile 390 px зафиксированы Playwright. На mobile отдельное утверждение подтверждает отсутствие горизонтального переполнения; карточка после перезагрузки сохраняет `A001 · B001` и признак обложки. Хэши и размеры находятся в `visual.json`, точный gate — в `verification.json`.

## Публикация и откат

Волна опубликована в [PR #21](https://github.com/rebit-pro/rabit-api/pull/21). Merge и deployment не выполняются автоматически; деплой объединяется с последующими волнами и выполняется отдельно на `app.morefoto.36.ru` только после согласованного этапа.

До первого production-применения откат — удалить приложение/миграцию вместе с данными тестового окружения. После появления production-разметки rollback миграции удаляет таблицы состояния, детей, назначений, обложек и идемпотентности, поэтому допустим только как отдельно подтверждённая destructive-операция; штатный откат приложения должен сохранять схему до совместимого forward-fix.
