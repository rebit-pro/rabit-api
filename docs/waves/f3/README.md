# F3 — короткая ссылка группы

Ветка `codex/f3-short-group-link` от main `0d02adf` (merge #160). Зависимости F2, E4 и E7 слиты, решения D05/D07/D10 приняты. План и журнал: `docs/plans/F3_short-group-link/`. Требование R05 из плана владельца `docs/plans/OPS-telemos-feedback-plan/`.

Сотрудник копирует для родительского чата короткую ссылку `https://app.morefoto36.ru/g/<псевдоним>` вместо 64-символьной. Псевдоним — непредсказуемые 10 символов, один на ключ галереи. Он открывает ту же галерею: корзина, квоты, заказы и вопросы работают по ключу, как раньше. Старые длинные ссылки продолжают работать.

## Решения (12.10.2026)

- **F3-DEC-01.** 10 символов из 32 (строчные латинские буквы и цифры без 0/o и 1/l), 50 бит. Пользователь выбрал 10 вместо рекомендованных 12; при ~10 000 групп и 1000 запросов в секунду это ~3,6 года перебора до первого попадания. Лимита запросов на публичную галерею нет — отдельная задача.
- **F3-DEC-02.** Домен прежний: `app.morefoto36.ru/g/<псевдоним>`, без изменений инфраструктуры.
- **F3-DEC-03.** Сотрудник копирует только короткую ссылку; длинная работает, но в интерфейсе не показывается.
- **F3-DEC-04.** Короткая ссылка открывает галерею и заменяет адрес на длинный `/g/<ключ>`; остальные публичные вызовы принимают только ключ.

## Контракты

| Где | Изменение |
| --- | --- |
| `mf_gallery_alias` | Новая таблица: `ALIAS` (PK, ascii_bin, CHECK формата), `TOKEN_HASH` (UNIQUE, FK на `mf_gallery_capability`, CASCADE), `CREATED_AT` |
| HND-02 | В ответе `galleryAlias` (строка или `null`) рядом с `galleryToken`. HND-01 по-прежнему без ссылки |
| HND-03 | Первая подготовка выдаёт ключ вместе с псевдонимом; повтор возвращает тот же; ключу без псевдонима он добавляется. Строка ключа и её `CREATED_AT` (нижняя граница T0) не меняются |
| MED-01 `GET /public/galleries/{gallery_token}` | Принимает 64 hex или псевдоним. В ответе `token` — длинный ключ, по которому витрина работает дальше. Неизвестный псевдоним и псевдоним отозванного ключа — 404 `GALLERY_NOT_FOUND` |
| Остальные публичные вызовы галереи, Commerce, Support | Без изменений: только 64-символьный ключ |
| `Rebit\Share\Contracts\Media\GalleryLinkInterface` | `GalleryLinkOutputDto::$alias` |

Реализация: `Morefoto\Media\Domain\Gallery\ValueObject\GalleryAlias`, `GalleryCapabilityRepository::attachAlias()/tokenByAlias()`, `GalleryLinks::ensure()`, `GetGalleryUseCase`. Новых API ID нет.

## Frontend

- «Ссылки и сроки» и история ссылок: «Копировать ссылку» и «Открыть галерею» — короткая ссылка (`handoff/rules.ts` `galleryLinkKey`; без псевдонима — длинная).
- `/g/<псевдоним>`: витрина получает ключ из MED-01 и заменяет адрес на `/g/<ключ>` с сохранением `?child=` (`gallery/composables/useGallery.ts`).
- Access-лог nginx frontend по-прежнему не пишет `/g/` и `/api/v1/public/galleries/`; тест `tests/ui/private-links-log.test.mjs` дополнен коротким адресом.

## Проверки

- PHPUnit `GalleryAliasTest`: формат и весь алфавит на 2000 выборках без повторов; псевдоним сводится к тому же ключу; длинный ключ без изменений, неизвестный псевдоним — 404; подготовка добавляет псевдоним только ключу без него и не переиздаёт ключ. `GroupLinkContractTest` — `galleryAlias` в HND-02. Повтор при коллизии и отзыв проверяются на MySQL (UNIQUE, E2E), не unit-тестом.
- Frontend unit: `galleryLinkKey` (`tests/commerce/handoff.test.mjs`), тест access-лога.
- E2E (группа b):
  - `z-links-preparation`: подготовка выдаёт псевдоним, он открывает галерею `preparing` с тем же ключом; повтор подготовки сохраняет псевдоним;
  - `cabinet-tables`: массовое «Скопировать ссылки» даёт короткие ссылки групп;
  - `zzzz-short-links`: псевдонимы фикстуры `open` и `digital` дают то же состояние окон E7, ту же группу и ключ, превью по ключу; псевдоним отозванного ключа, неизвестный, в верхнем регистре, длиннее и с запрещёнными символами — 404; `/catalog` по псевдониму — 404; desktop/mobile: `/g/<псевдоним>?child=A` → адрес `/g/<ключ>?child=A`, кадр виден, нет горизонтального скролла, неизвестный псевдоним — «Ссылка недействительна».
- MySQL `verify-links.php`: у ключа группы ровно один псевдоним нужного формата после двух подготовок; у каждого действующего ключа с сохранённым `TOKEN` есть псевдоним; повтор миграции не меняет ни одного псевдонима.

## Выкладка

Миграция `20261012180001` создаёт `mf_gallery_alias` и выдаёт псевдонимы действующим ключам с сохранённым `TOKEN` (группы, подготовленные начиная с F2). Ключи не меняются, уже отправленные длинные ссылки продолжают работать.

Порядок: preview → `migrate.sh up 20261012180001` → backend → frontend. Backend без таблицы отвечает ошибкой на HND-02/03, поэтому миграция идёт до переключения backend. Ключу, выданному между миграцией и переключением, псевдоним добавит следующая подготовка; до этого сотрудник копирует длинную ссылку. Frontend без псевдонима в ответе тоже копирует длинную.

Preview — сколько ключей получат псевдоним:

```sql
SELECT COUNT(*) AS keys_to_alias FROM mf_gallery_capability WHERE REVOKED = 0 AND TOKEN IS NOT NULL;
```

Откат — возврат кода; `down()` удаляет таблицу. После того как короткие ссылки ушли в родительские чаты, откат их ломает (длинные продолжают работать), поэтому таблицу при откате кода оставлять.

## Ограничения

- Лимит запросов к публичной галерее не вводился (риск DEC-01).
- QR-коды, внешние сокращатели, переиздание ключа из интерфейса — вне scope.
- Ключи до F2 без сохранённого `TOKEN` псевдонима не получают: их ссылку и так нельзя скопировать.
