# E3 — условия продаж и переопределения группы

Статус: готово к ревью, обязательная локальная приёмка завершена. Ветка `codex/e3-sales-conditions` от `main` `d78862280cd6cf21ab829dc782459203ea66a3ac`; зависимости C3 и E2 слиты. Реализация находится в Rabbit P2P / `rabit-api`, каноническая продуктовая документация остаётся в совместном проекте MoreFoto/BorrowPhoto.

## Принятые правила

Пользователь закрыл D02–D05 для этой волны: продукция и цены не создаются seed-данными; фотография считается отдельно для каждого ребёнка; порог подарка считается по физическим товарам после скидки и отдельно для каждого ребёнка; подарок покрывает только один активный `bundle`, а не одиночные электронные кадры; скидка сотрудника 50% применяется только к отмеченным позициям и только по доверенному серверному признаку; суммы хранятся целыми копейками RUB, итоговая половина нечётной цены округляется вверх; условия группы по умолчанию наследуют общие.

Подарок и скидка одной строки не складываются: подарок имеет приоритет. Оплаченный снимок не относится к E3; будущий quote E4 обязан сохранять `catalogRevision` и `conditionsRevision`, чтобы изменение условий инвалидировало неоплаченный расчёт, но не исторический снимок покупки.

## Результат волны

Добавлены COM-04/05 `GET/PUT /api/v1/catalog/conditions` и COM-06/07 `GET/PUT /api/v1/groups/{group_id}/conditions`. Все операции доступны только организатору, используют optimistic CAS и идемпотентность; доступ проверяется до replay. Публичный UUID группы разрешается через контракт Organization, хранение условий остаётся в Commerce.

Миграция создаёт версионированные общие/групповые условия, переопределения продукции и журнал идемпотентности без демонстрационного ассортимента. Группа без записи имеет revision 0 и наследует общие условия. Общая запись меняет цену/доступность/скидку каталога и одновременно продвигает `catalogRevision`; групповая запись фиксирует собственную revision и ссылку на текущие общие условия.

`SalesPolicy` — единая серверная политика для E4: валидирует доступность и фото, считает физический порог после скидки по ребёнку, выбирает bundle-подарок, запрещает двойной bundle ребёнка, не складывает скидку с подарком и работает целочисленно. Frontend использует те же правила в существующей корзине.

Live UI подключён к реальному API: общий редактор находится на странице каталога, групповой — в съёмке. Черновик и точный запрос с Idempotency-Key переживают потерянный ответ. Групповой список read-only; изменение всего прайса выполняется одной явной кнопкой.

## Публикация и откат

Волна опубликована в [PR #20](https://github.com/rebit-pro/rabit-api/pull/20). Merge и deployment не выполняются автоматически; после ревью пользователь сам решает момент merge. Деплой объединяется с последующими волнами и выполняется отдельно на `app.morefoto.36.ru` только после согласованного этапа.

До первого production-применения откат — удалить приложение/миграцию вместе с данными тестового окружения. После production-записей rollback миграции удаляет четыре E3-таблицы и поэтому допустим только как отдельно подтверждённая destructive-операция; обычный откат приложения должен сохранять схему до совместимого forward-fix.
