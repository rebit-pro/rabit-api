# J2 — письмо родителю со ссылкой на оплаченный заказ

Ветка `codex/j2-buyer-files-email` от main `d1741d5` (после L1). Зависимости H1, J1, E8, J4 слиты; D07, D10 приняты; решения J2-DEC-01…07 приняты пользователем 15.10.2026. План и журнал: `docs/plans/J2_buyer-files-email/`.

После подтверждённой оплаты родитель получает письмо со ссылкой на страницу своего заказа: состав, электронные фото и архив (J1 + J4), срок скачивания. На странице заказа видно, куда и когда ушло письмо, и есть «Отправить ещё раз».

## Решения

| ID | Принято |
| --- | --- |
| J2-DEC-01 | Ссылка в письме — на страницу оплаченного заказа отдельным ключом письма; ссылка, сохранённая при оформлении, работает дальше; срок — месяц файлов. **Уточнение реализации:** ключ письма выводится HMAC из серверного секрета, поэтому повторное письмо несёт ту же ссылку и не отзывает прежнюю — иначе «Отправить ещё раз» со страницы, открытой по письму, закрыло бы её же (404) |
| J2-DEC-02 | Заказы, оплаченные до выкладки J2, автописьма не получают (у них нет момента подтверждения оплаты `PAID_RECORDED_AT`); письмо можно запросить кнопкой |
| J2-DEC-03 | Адрес — email заказа без подтверждения; на странице заказа видно адрес и судьбу письма; смена адреса — J3 |
| J2-DEC-04 | Оператору — только журнал до J3 |
| J2-DEC-05 | Флаг `MOREFOTO_ORDER_EMAIL_ENABLED` (Commerce), по умолчанию выключен: письма копятся (`held`) и не уходят; после включения диспетчер ставит их в H1 |
| J2-DEC-06 | При включённой отправке подсказка у email: «Ссылку на заказ покажем после оформления. На этот адрес отправим ссылку на заказ после оплаты» (`capabilities.orderEmail` каталога) |
| J2-DEC-07 | «Отправить ещё раз» — не чаще раза в 10 минут и не больше 5 в сутки на заказ |

## Как устроено

- **Событие без outbox.** `applyPayment('paid')` пишет `mf_order.PAID_RECORDED_AT` (момент подтверждения сервером). Cron `app:files:order-emails` раз в минуту читает подтверждённые оплаты по курсору (`mf_file_delivery_cursor`, перекрытие 10 минут на поздний commit), создаёт одно автописьмо на заказ (`mf_file_delivery`, уникальность `AUTO_ORDER_ID`) и ставит ждущие письма в H1 вне транзакций. Платёжная транзакция не меняется.
- **Повтор безопасен.** Ссылка и текст письма определяются заказом, ключ дедупликации H1 — `order-email:<id письма>`: сбой между постановкой и записью статуса даёт то же письмо, H1 не отправит его дважды. Поздняя оплата (G1) и заказ с истёкшим месяцем файлов письма не получают (`cancelled`).
- **Ключ письма.** `mf_order_access_key.KIND = 'email'`, отдельная уникальность действующего ключа письма (`ux_mf_order_key_email`); ключ покупателя — по-прежнему один действующий. В БД — только SHA-256; срок — конец месяца файлов. Перевыпуск ключа заказа сотрудником (D07, когда появится) отзывает и ключ письма.
- **H1.** Consumer `files-order-email`, до 10 попыток. После `accepted`/`failed` H1 очищает текст и HTML письма (ссылка — секрет), хеш содержимого остаётся для дедупликации; у `unknown` текст сохраняется для подтверждённого повтора. Очистка касается и приглашений/сброса пароля.
- **API** (по ключу страницы заказа, `X-Order-Key`): `GET /public/orders/current/file-deliveries` — сводка; FIL-05 `POST` — повтор (Idempotency-Key, 202); FIL-06 `GET …/{id}` — статус `pending | accepted | failed | cancelled` (`accepted` — передано почтовому серверу, не доставка).
- **Адрес ссылки:** `MOREFOTO_APP_URL`, по умолчанию `https://app.morefoto36.ru`.

Реестр соседнего MoreFoto: `morefoto-contract.patch` (FIL-05/06) — накладывается после патчей `OPS-telemos-feedback-plan` и L1.

## Выкладка (stage)

1. Миграция адресно: `migrate.sh up Version20261015180001` — **до** переключения backend (новый Commerce пишет `PAID_RECORDED_AT` и `KIND`).
2. Backend (12 сервисов, как после L1) + DI-smoke (`DispatchOrderEmailsUseCase`, `PublicFileDeliveryController`, `OrderEmailLinkInterface`).
3. Cron `app:files:order-emails --limit=100` раз в минуту — в цикл `morefoto_stage_files_dispatcher` или отдельным циклом; контейнеру нужен `REBIT_ENCRYPTION_KEY` (есть у files_dispatcher).
4. Frontend.
5. **Отправка остаётся выключенной.** `MOREFOTO_ORDER_EMAIL_ENABLED=1` в env FPM и цикла писем — только после того, как владелец получит штатное письмо (сброс пароля или приглашение) в свой ящик (#161). До этого письма копятся `held`; после включения уйдут по заказам, оплаченным после выкладки и ещё в сроке файлов.

Откат — возврат кода; `down` миграции удаляет ключи писем (ссылки из отправленных писем перестанут открываться) — после включения отправки не выполнять.

## Ограничения

- Реальная доставка E2E не проверяется: на стенде нет почтового сервера. Проверка — письмо владельцу на stage.
- Перевыпуск ссылки сотрудником, смена адреса и выдача персоналом — J3 (FIL-07/08).
- Опечатка в email отправит ссылку чужому (DEC-03); ссылка открывает заказ без регистрации.
