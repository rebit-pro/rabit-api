# План MVP: ЮKassa, чеки и E6

Актуальное решение от 22.09.2026 — в [плане](../../plans/sberpay-start-plan/plan.md) и [журнале](../../plans/sberpay-start-plan/progress.md). PR #35 сохраняет историческое имя ветки, но первый провайдер теперь ЮKassa, а прямой СберПэй — необязательный резерв.

- Base: main `4b507b3b3c27719888e38f582b48e6a56c0c5946`, E5 merged по PR #37.
- E6: самостоятельная опция расходов в общей цене, шаг вверх до 50 ₽; зависит от E3/E5, не от банка. Выбор метода оплаты цену не меняет. Статус planned означает отсутствие реализации; readyFromMain означает только готовность зависимостей.
- G1/G2/I2: платёжная страница и сверка ЮKassa, встроенные чеки, полный/частичный возврат с резервом. Реализация G1 ждёт F2 и оставшихся решений.
- 3,8% — редактируемая расчётная ставка пользователя. Публичное предложение ЮKassa указано без применимого НДС, СБП — индивидуально; итоговый тариф проверяется по договору.

## Проверки

`verification.json` содержит фактические результаты: два DAG валидатора (41 волна, 99 API ID, 35 WNN, 10 отрицательных fixtures), сохранение владельцев исходных ID, арифметику, воспроизводимость генерации, API и offline Postman.

В этом срезе нет PHP/Vue runtime-изменений и реальных HTTP/банковских/E2E-прогонов. Проверены только документы, схемы графа и формула спецификации. Исторический `../sberpay-start/verification.json` относится к 21.09 и не является текущим подтверждением ЮKassa.

## Канонический план MoreFoto

`morefoto-plan-update.patch` — **добавочное** изменение относительно локального канонического плана на 22.09 до этой задачи. Начальные SHA файлов записаны в `verification.json`. Patch сохраняет уже имевшиеся решения F2 → D3 и дашбордов N1; их код и изменения не перенесены в ветку PR #35.

Поэтому граф PR и канонический граф отличаются только существовавшими соседними планами F2/D3/N1 и их evidence. Общие paymentIntegration/E6/G1/G2/I2 равны. Готовые по графу PR: E6. В каноническом плане: E6 и F2. Статусы не заменяют проверку GitHub перед реализацией.

Исторический `../sberpay-start/morefoto-plan-sync.patch` сохранён как исходный срез 21.09; не применять добавочный patch к произвольной версии MoreFoto без проверки исходных SHA. Применимость текущего patch к уже обновлённым документам проверена командой:

```sh
git -C /home/user/MoreFoto apply --check --reverse /home/user/rabit-api-worktrees/yookassa-plan/docs/waves/yookassa-mvp/morefoto-plan-update.patch
```

Канонический каталог MoreFoto не является Git-репозиторием, поэтому адресные изменения представлены patch в PR. Замороженные W00, исходники Orteka, runtime/config/secrets и другие checkout не менялись.
