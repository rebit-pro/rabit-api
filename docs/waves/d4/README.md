# D4 — коррекция разметки переданной группы без заказов

Ветка `codex/d4-sent-markup-correction` от main `50c8ee1` (merge E7, PR #162). Зависимости D2, D3, F2, E5 и E7 слиты, решения D03, D05, D07 и D11 приняты. План и журнал: `docs/plans/D4_sent-markup-correction/`. Волна определена в графе из плана владельца `docs/plans/OPS-telemos-feedback-plan/` (PR #173); PR D4 открывается после его merge.

Организатор или куратор учреждения исправляет ошибочную разметку кадров после передачи ссылки родителям, пока у группы нет ни одного заказа, включая неоплаченные. На время исправления продажа группы на паузе. T0, сроки печати и электронных фото, ссылка галереи и её ключ не меняются, повторная передача не нужна.

## Правила (решения D4-DEC-01…06, приняты 11.10.2026)

- **Сеанс с паузой продаж.** «Начать исправление» под эксклюзивной блокировкой строки группы проверяет отсутствие заказов и ставит паузу. «Завершить исправление» проверяет готовность материалов, как перед передачей ссылки, и снимает паузу.
- **Кто.** Организатор и куратор учреждения группы: новое право `media.correct`. Подготовка до передачи остаётся за `media.manage` организатора.
- **Что правится.** Существующие команды: загрузка, привязка к коду ребёнка, удаление кадров, обложка. Перенос набора в другую группу (MED-07) — только до передачи (D11). Операции «снять кадр с ребёнка» нет и до передачи — это отдельная задача.
- **Когда.** Начать можно, пока группа продаёт (`open` или `digital`). До передачи — 409 `LINK_NOT_SENT`, после окончания продаж — 409 `GALLERY_CLOSED`. Завершить можно всегда, в том числе после окончания продаж.
- **Атомарность с заказом.** Заказ (COM-10) и расчёт корзины (COM-09) читают строку группы разделяемой блокировкой в SERIALIZABLE, а старт берёт её эксклюзивно. Проходит только одна сторона: заказ, появившийся раньше, даёт 409 `GROUP_HAS_ORDERS`, а заказ после старта — 409 `GALLERY_UPDATING`. Команды D4 повторяют транзакцию после deadlock.
- **Старые расчёты.** Старт и завершение повышают ревизию группы, а отпечаток quote перечисляет все связи кадров. Сохранённый расчёт после исправления отклоняется: `QUOTE_STALE`, `INVALID_CART` или `PRICE_CHANGED`.

## Контракты

| Где | Изменение |
| --- | --- |
| `POST /api/v1/groups/{id}/markup-corrections` | Новая команда. Тело `{revision}`, заголовок `Idempotency-Key`. Ответ `{revision, startedAt}`. Отказы: 409 `LINK_NOT_SENT`, `CORRECTION_IN_PROGRESS`, `REVISION_CONFLICT`, `GROUP_HAS_ORDERS`, `GALLERY_CLOSED`; 403 для воспитателя и руководителя; 404 для чужой группы |
| `POST /api/v1/groups/{id}/markup-correction-completions` | Новая команда. Тело `{revision, signature}`. Ответ `{revision, startedAt: null}`. Отказы: 409 `CORRECTION_NOT_STARTED`, `REVISION_CONFLICT`, `SIGNATURE_CONFLICT`, `LINK_NOT_READY` |
| `GET /api/v1/groups/{id}/link`, `GET /api/v1/group-links` | `markupCorrectionAt` (ATOM в зоне группы или null); в карточке ещё `markupCorrectable` |
| История ссылки | События `markup_started` и `markup_finished`; у второго — подпись опубликованных кадров |
| `GET /public/galleries/{token}` | Новое поле `updating` |
| `POST …/quotes`, `POST …/orders` | Во время исправления — 409 `GALLERY_UPDATING` |
| MED-03, MED-05, MED-06, удаление кадров | После передачи разрешены только в режиме исправления, по праву `media.correct`; вне режима — по-прежнему `GROUP_LOCKED` / `GROUP_MEDIA_LOCKED` |
| MED-02, MED-04, превью сотрудника | Читаются по `media.correct`: организатор и куратор своего учреждения |
| Профиль сотрудника | Куратор получает право `media.correct` |
| Контракты rebit.share | `GroupMarkupCorrectionInterface` (Organization), `GroupOrdersInterface` (Commerce); `markupCorrectionAt` в `GalleryGroupOutputDto` и `GroupDirectoryItemOutputDto`, `groupCorrecting` в `MediaScopeOutputDto` |

## Хранение и миграция

Миграция `20261011180001`:
- добавляет HL-поле `UF_MARKUP_CORRECTION_AT` (DATETIME NULL) в `b_hlbd_mf_group`;
- добавляет CHECK `ck_mf_group_markup_correction`: исправлять можно только переданную группу;
- пересоздаёт CHECK `ck_mf_group_link_history` с видами `markup_started` (без дат, причины и подписи) и `markup_finished` (с подписью 64 символа).

Повторный `up()` безопасен. `down()` отказывает, пока открыто исправление или в истории ссылок есть события D4.

## Выкладка и откат

1. Backend и точечно `migrate up 20261011180001` — одним окном.
2. Затем frontend: без него кнопок исправления нет, а галерея не показывает плашку обновления, хотя расчёт корзины уже отклоняется (`GALLERY_UPDATING`).
3. Перед выкладкой проверить, что на стенде нет открытых правок разметки (до D4 их быть не может).

Откат: frontend, затем backend и `migrate down 20261011180001`. Если исправления уже были, `down()` откажет — это защищает историю ссылок.

## Ограничения

- Уведомлять родителей об обновлении галереи D4 не умеет.
- Открытое и забытое исправление держит продажу на паузе: карточка ссылки и рабочее место показывают его, а сроки продолжают идти.
- Корзины покупателей хранят assignmentId: удалённый при исправлении кадр даёт `INVALID_CART`, и корзина просит уточнить выбор.
