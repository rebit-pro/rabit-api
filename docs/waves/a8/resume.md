# Передача A8 на ревью

Постоянный worktree: `/home/user/rebit-p2p/api/var/worktrees/a8`, ветка `codex/a8-real-e2e`. Основной checkout остаётся на main. Временный checkout предыдущей попытки был утрачен при перезапуске WSL; восстановленная версия проверена заново. Текущие результаты находятся в [verification.json](verification.json).

Docker Desktop восстановлен с явного разрешения пользователя. Перед перезапуском оба каталога с аварийными временными сокетами перенесены в резервные копии. Сброс Docker, удаление существующих образов и рабочих БД не выполнялись. Тестовые ресурсы A8 имеют собственные метки и очищаются отдельно.

Перед merge:

1. Проверить актуальный `main` относительно base из verification.json; при изменениях повторить затронутые проверки на main плюс только A8.
2. Проверить результаты всех обязательных наборов и границы live/demo. Команда повторения реального E2E — `make test-e2e`; визуальная процедура описана в README.
3. Провести ревью PR. Merge и deployment выполняются отдельно по решению пользователя; автоматически PR не сливать. GitHub Actions остаётся отключённым, YAML сохранён.

Следующая независимая продуктовая волна — C3 (съёмки, группы и календарь) после уже слитой C2; D08/D10 приняты. C3 имеет собственные ORG-06/07/08/09/10/12 и отдельную ветку от актуального main. Реализация C3 в A8 не входит. Код незамерженной A8 не переносить в её ветку.

Read-only подготовка C3 выявила два решения для следующего среза: D08 требует причину замены назначения, но текущие DTO/API-поля её не содержат; ORG-06/08 требуют уточнения пагинации и проекции групп в генераторе контракта. Журнал C2 также потребуется расширить типом агрегата новой миграцией: текущая уникальность `(aggregateId, toRevision)` недостаточна для учреждения, съёмки и группы с пересекающимися внутренними ID. Это не реализовано в A8.

В текущем main до merge A8 нет frontend и browser harness. C3 может независимо реализовать backend после C2, но полноценную приёмку продуктового редактора необходимо проводить на обновлённом main после merge A8. Отдельный HTTP-вызов из Chromium не заменяет эту проверку интерфейса.
