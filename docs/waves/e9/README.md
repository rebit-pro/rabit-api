# E9 — продажи группы в кабинете воспитателя

Ветка `codex/e9-teacher-sales` от main `e728d8c`. Зависимости B2, E5, G1 и U6 слиты. План и журнал: `docs/plans/E9_teacher-sales/`. Волна добавлена в граф PR #207 (`docs/plans/OPS-waves-e9-j5/`).

Воспитатель входит в кабинет и в «Обзоре» у каждой своей группы видит блок «Продажи»:

- сколько заплатили родители;
- оплаченные заказы;
- купившие семьи;
- печатные фото;
- цифровые файлы;
- разбивка печати по форматам.

Считаются только оплаченные заказы. Личных данных родителей нет.

## Решения (16.10.2026)

- **E9-DEC-01.** «Цифровые файлы» — оплаченные digital-кадры. Бесплатные копии печати J4 и подарок за порог продажей не считаются.
- **E9-DEC-02.** «Купившие семьи» — уникальные дети группы, у которых есть хотя бы один оплаченный заказ.
- **E9-DEC-03.** Интерфейс — только у воспитателя. Организатор и куратор получают ту же сводку через API в своей области.
- **E9-DEC-04.** Комплект «все фото ребёнка» — оплаченная цифровая покупка, но число кадров в снимке заказа не хранится. Поэтому он показан отдельной строкой: «и N комплектов „все фото ребёнка“».
- **E9-DEC-05.** Поздняя оплата (ждёт решения SET-07) не входит, как в L1 и J2. Возвратов до I2 нет.

## Контракт COM-14

`GET /api/v1/groups/{group_id}/sales-summary`, Bearer.

```json
{
  "data": {
    "groupId": "…",
    "paidOrders": 4,
    "families": 3,
    "prints": 9,
    "digitalFiles": 5,
    "bundles": 1,
    "paidTotal": 1234550,
    "products": [{ "id": "…", "name": "Печать 10×15", "prints": 7 }]
  }
}
```

- `paidTotal` — копейки, сумма `TOTAL` оплаченных заказов.
- `prints` — сумма `quantity × printCount` по physical-строкам.
- `products` упорядочены по убыванию отпечатков; название продукции берётся из снимка заказа.
- Область:
  - organizer — любая группа;
  - curator — группы своих учреждений;
  - teacher — свои назначенные группы;
  - остальные роли — 403 `FORBIDDEN`;
  - чужая, несуществующая или некорректная группа — 404 `GROUP_NOT_FOUND`;
  - без входа — 401.

Реализация в `morefoto.commerce`:

- `GroupSalesController` → `GetGroupSalesUseCase`;
- `SalesAccess` строит область через Access `StaffRequestAccessInterface`;
- группа берётся из Organization `GroupDirectoryInterface::find`;
- `GroupSalesRepository` делает два SQL-чтения по индексу `ix_mf_order_group`: итоги и печать по продукции.

Миграций нет.

## Frontend

`frontend/src/modules/morefoto/overview/GroupSales.vue` в карточке группы «Обзора» воспитателя (`LiveOverview.vue`):

- сумма оплат и четыре счётчика;
- строка комплектов;
- печать по форматам;
- «Продаж пока нет» для группы без оплаченных заказов;
- ошибка загрузки с кнопкой «Повторить».

Правила текстов — `sales-rules.ts`.

- E2E `zzzzzzzzzzz-teacher-sales` (группа b, после J4/J2 и до L1):
  - COM-14 совпадает с независимым расчётом по COM-12 той же группы;
  - новый неоплаченный заказ ничего не меняет;

## Выкладка

Только код backend и frontend: миграций и новых сервисов нет. Порядок: backend (FPM и backend nginx) → DI smoke `GetGroupSalesUseCase`/`GroupSalesController` → frontend. Frontend без нового backend показывает в блоке ошибку с повтором; остальной «Обзор» работает.

## Ограничения

- Организатор и куратор не видят блок в интерфейсе (E9-DEC-03). Полные финансы (комиссии, возвраты, вознаграждение) — N1.
- Воспитателю нужен вход в кабинет: приглашение B2 и рабочая доставка письма (#161).
